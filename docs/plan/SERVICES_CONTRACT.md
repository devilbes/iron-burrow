# Контракт сервисов — Iron Burrow

Машинная версия — `docs/plan/SERVICES_CONTRACT.json` (гейт `npx studio-gates check:services-contract`). Сценарии проверки — `qa/scenarios/services/<function>.json` (пишутся до кода, шаги кода их не меняют). Методы — только из `docs/platform/sdk-methods.lock.json`.

- SDK: `@manygamescorp/core` 1.0.0-rc.30, состав приложения `modulesRevision 2`, `lockHash 881abf2b…c530` (MCP `sdk.modules.set` apply этим шагом, `sdk.kit.get {target:"web"}`).
- Модули `platform.json sdk.modules`: `ui-kit`, `hud`, `inventory`, `progress` (+ `levels`), `daily-rewards`, `iap`, `leaderboards`, `profile-pack` (`kv`, `gamestate`, profile-ui), `realtime`. Не подключены: `ads` (рамки потока — рекламы нет), `scheduling` (beta, liveops = false; недельный цикл даёт период доски `siege_best`). `profile` — ядро, в `sdk.modules` не добавляется.
- Ядро (`configs`, `analytics`, `profile`, `portal`, `time`, `l10n`, `device`, `bus`) в `platform.json sdk.modules` не объявляется, а гейт требует модуль из этого списка → в поле `module` записан объявленный модуль-носитель (см. «Чего не хватает у платформы»). Владелец метода — всегда префикс в `methods`.
- Сохранений, конфигов и прогресса своих нет. Всё, что живёт дольше забега, — в сервисах ниже.

## Порядок данных на платформе (публикует game-records)

inventory-entity → iap-product → iap-offer → плейсменты (`ads.game.placements`, затем `iap.placements`) → level-set `campaign`, `siege` с наградами → настройки daily-rewards (`sdk.modules.set`) → leaderboard-definition (`leaderboards.definitions.put`, не configs) → config-record с id из ответов. Квитанция — `docs/plan/SERVICES_READBACK.json`, гейт `check:contract-platform`.

## Чего не хватает у платформы

1. **Ядро SDK вне `platform.json sdk.modules`.** Гейт `check:services-contract` требует модуль функции из `platform.json sdk.modules`, а `configs`, `analytics`, `profile`, `portal` — ядро (`@manygamescorp/core`), его в этот список не добавляют (`sdk.modules.list`: «never add profile to sdk.modules»). Искал: lib/services-contract.mjs гейта, MCP docs.search «SERVICES_CONTRACT core configs module». Получил: только объявленные модули. Попыток: 1. Нужно: допустить `module: "core"` для методов ядра. Обход: модуль-носитель (`progress` для configs, `ui-kit` для analytics, `profile-pack` для profile) с префиксом владельца в `methods`.
2. **Снимок методов.** Инструмента `sdk.methods.list` (на него ссылается гейт) в tools/list нет; `vendor/@manygamescorp/docs/base/sdk-methods.lock.json` содержит объекты только ядра, а гейт ждёт строки `<ns>.<method>`. Лок собран из `docs/api.json` комплекта `sdk.kit.get` (sha256 совпадает с файлом комплекта). Нужно: один формат лока и инструмент его выдачи для выбранного состава.
3. **Получение ежедневной награды.** В `mod-daily-rewards` нет метода claim: модуль «never issues rewards», день получается «только с серверной операцией» (`operationId`). Точный тип действия `progress.send` для claim в docs не описан — уточняет интеграция по `mod-progress/contracts`.
4. **Стартовый грант.** Отдельного метода выдачи разового гранта нет; выбран бесплатный оффер `start_grant` с лимитом 1 (`iap.purchase` «claims a free one»). Нужно подтверждение, что iap принимает оффер без продукта с лимитом на игрока.
5. **Аналитика.** `analytics.sendEvent` без провайдера — no-op; модуля телеметрии в каталоге нет, события до платформы не доходят.
