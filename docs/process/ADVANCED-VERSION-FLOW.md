# Продвинутая версия игры — журнал шагов (основа для флоу)

Источник: доводка Iron Burrow (360) до «топовой» версии, 27.11.2026. Каждый шаг — что сделано,
вход, выход, кто (я / агент), проверка. По этому журналу строится флоу «advanced-version».

## Шаг 0. Сбор требований владельца
- Вход: игра в QA, замечания владельца (поток сообщений со снимками).
- Действие: каждое замечание → пункт с номером в TODO (IRON-BURROW-TODO.md), снимок → описание дефекта
  словами (что видно, что ждали). Пункты группируются по частям (ядро, экономика, UI, рендер, сюжет, уровни).
- Выход: список 1…30 пунктов.

## Шаг 1. Обход игры новым гостем
- Инструмент: `tools/tour.mjs <url> <W> <H> <dir>` — снимки главного, магазина, ежедневки, рейтинга,
  профиля, настроек, уровня; ошибки консоли/сети; список кнопок.
- Размеры: 1440×900 и 844×390 (DPR 2).
- Урок: первое окно (стартовый набор) надо закрывать кнопкой Collect, иначе все снимки одинаковые.

## Шаг 2. Исходники локально
- Владелец подключает GitHub к проекту Студии (синхронизация в `main`).
- `gh repo clone <owner>/<repo>`; ключ MCP приложения — файл `.env.local` (в git не идёт;
  `MANYPLAY_MCP_URL`, `MANYPLAY_MCP_KEY`).
- SDK в `vendor/` (в git его нет): каталог версии с CDN
  `https://games.utlragames.com/sdk/catalog/<ver>/catalog.json`, раскладка скриптом client-sdk
  `scripts/vendor-project.mjs --catalog … --project … --modules <ids> --no-verify`
  (в rc.54 в каталоге две записи `ads` — проверку дубликата id пришлось обойти); `package.json`
  после раскладки вернуть (`git checkout package.json`).
- Проверка: `npm install && npm run check:fast` — типы и бандл зелёные.

## Шаг 3. Дизайн-контракт
- Файл `docs/game/DESIGN-V2.md`: цель и нарратив, блоки 10×10 с новым элементом и боссом в каждом,
  враги и ИИ, кривая сложности, экономика (мягкая валюта, награды, миссии, магазин), мастерская,
  аналитика, рендер, **владение файлами по частям** (чтобы части шли параллельно без конфликтов).
- Ветка `v2` от `main`, коммит контракта.

## Шаг 4. Части параллельно (агенты, свои worktree и ветки)
Общий шаблон брифа: прочитать контракт + AGENTS.md + свои файлы; `git worktree add ../<repo>-<part>
-b v2-<part> origin/v2`, скопировать `vendor/`, `npm install`; менять только свои файлы; готово =
`npm run check:fast` (типы, бандл, свои тесты), коммиты с трейлером, `git push -u origin v2-<part>`;
без слияний, PR, публикаций; отчёт ≤15 строк. Брифы — `docs/process/briefs/*.md`.
| Часть | Модель | Ветка |
|---|---|---|
| Ядро: ИИ по полю потоков, новая клетка, новый враг, боссы с фазами, сложность по блокам | opus | v2-core |
| Экономика: мягкая валюта, награды только валютой, миссии блока, магазин, мастерская, топ-бар | opus | v2-eco |
| UI: туториал, кампания со стрелками, рейтинг, профиль, настройки, storeId | sonnet | v2-ui |
| Рендер: Pixi v8 WebGPU→WebGL2, атласы, пулы, замер FPS | opus | v2-render |
| Сюжет: персонажи, сцены 5 языков (mod-narrative), реплики для озвучки | opus | v2-story |
| Уровни: 100 уровней по контракту (после ядра) | — | v2-levels |

## Шаг 5. Слияние и проверка (впереди)
- Слить ветки частей в `v2` по порядку: core → levels → eco → story → ui → render; после каждого
  `npm run check:fast`.
- Записи `configs/remote/*` → `npm run records` → публикация через MCP `configs.write`.
- Сборка: MCP `projects.upload.*` → `builds.create` → `projects.qa.publish`.
- Обход шага 1 на двух размерах, замер FPS (`window.__ibPerf`), сверка с пунктами TODO.

## Шаг 6. Арт и озвучка в Студии (впереди)
- Список файлов арта и реплик — `docs/game/NARRATIVE.md`, `docs/game/VOICE-LINES.md`.
- Генерация — в треде Студии (Codex — картинки, ElevenLabs — голос), только `assets/`.
