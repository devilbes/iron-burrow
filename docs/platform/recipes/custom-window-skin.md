# Свой вид игры (скин)

Окна сервисов, верхнюю панель, HUD, нижнее меню, загрузку и экраны игры рисует UI Kit со скином
ManyPlay. Свой вид игра задаёт в `src/skin/`, обвязку (`src/shell/`) не трогает.

| Файл | Что в нём | Кто правит |
|---|---|---|
| `src/skin/theme.css` | все цвета, радиусы и шрифты переменными | игра; **для перекраса — только этот файл** |
| `src/skin/sheets.ts` | `COMMON` — общий лист всех компонентов; `COMPONENTS` — короткие листы отдельных компонентов | игра |
| `src/skin/art.ts` | `ASSETS` — растровые детали по ключам, `FONTS` — шрифты; файлы — в `assets/skin/` | игра |
| `src/skin/icons.ts` | значки `icon-*` → перекрашенный атлас и свой лист (входит в `ASSETS`) | `node scripts/skin-icons.mjs`, руками не править |
| `src/skin/index.ts` | сборка `SKIN`; `closePosition`, `displayTitle`; `SKIN_WEIGHT_LIMIT` | игра (поля) |
| `src/shell/skin.ts`, `src/shell/stock-colors.ts`, `src/shell/button-tint.ts` | подключение поверх ManyPlay; цвета стока, переведённые на переменные; растровые кнопки из одной серой картинки | не трогать; `stock-colors.ts` делает `node scripts/stock-colors.mjs` |

Как шаблон поставляется, все значения стоковые, кроме полос панелей: они прозрачные, и фон сцены
идёт под топбаром и нижним меню до краёв экрана (раздел «Фон сцены и панели»). Источник правды по
киту — `vendor/@manygamescorp/ui-kit/README.md` (раздел «Свои скины»), `ui-kit/dist/skin-spec.d.ts`,
`ui-kit/dist/skin-keys.json` (все ключи), листы `ui-kit/dist/skin-bundles/manyplay/css/<компонент>.css`
(в старых SDK — `skin-manyplay/dist/css/`).

## Как это устроено (UI Kit 1.0.0-rc.30)
- Один слой: скин игры `extends` ManyPlay (`defineSkin`). Лист компонента у потомка заменяет лист
  родителя целиком, поэтому обвязка пишет свои правила **после** текста листа ManyPlay.
- В shadow root каждого компонента кит кладёт листы в таком порядке: лист компонента (ManyPlay +
  `stock-colors.ts` + правила обвязки + `COMPONENTS`), затем цель `*` — `theme.css` + `COMMON`.
  Цель `*` попадает во все компоненты кита и в экраны самой игры; `shell` — в документ.
- Каждый стоковый лист начинается с палитры на `:host` и затем переводит её на входы
  `--mp-card-*` (`--mp-night: var(--mp-card-background, …)` и т. д.). Поэтому `theme.css` идёт
  в `*` (после листа компонента) и задаёт **входы**, а не `--mp-night`/`--mp-violet` на `:host`
  (список производных — `STOCK_DERIVED`; проверка это ловит). Поле `tokens` у `defineSkin` для
  этого не годится: кит кладёт его перед листом компонента, и палитра стока его перебивает
  (проверено: `--mp-points` через `tokens` остаётся стоковым, `--mp-card-surface` доходит).
- Цвета, которые сток пишет литералами (16 правил в 11 листах, плюс палитра загрузки без
  привязки к `--mp-card-*`), обвязка повторяет через переменные (`stock-colors.ts`); значения по
  умолчанию — те же литералы в `theme.css`. Список для команды кита —
  `node scripts/stock-colors.mjs --list`.
- `theme.css` сборка минифицирует на его пути (`scripts/build.mjs`: `.css` из `src/` → `dist/app/`,
  `src/skin/theme.css` → `dist/app/skin/theme.css`), обвязка читает его при запуске одним запросом к файлам игры.

## Порядок работы
1. **Цвета, радиусы, шрифты — `theme.css`.** Раздел «Palette» (48 строк) задать полностью: этого
   достаточно, чтобы в окнах, панелях, меню, загрузке и экранах игры не осталось ни одного
   стокового цвета. «Derived» следуют за палитрой (`var()`, `color-mix`) — менять только чтобы
   разорвать связь. Шрифты — три роли `--mp-font-display`, `--mp-font-ui`, `--mp-font-body`.
2. **Общий лист — `COMMON` в `sheets.ts`.** Рамка окна, шапка, кнопки, крестик — один раз для всех
   окон. Положение крестика — `closePosition` в `SKIN` (`head-right`, `head-left`, `corner-out`),
   его картинка — ключ `icon-close` (ключ кита `close` — запасной, стоковый `icon-close` его
   перебивает); заголовки остаются текстом: `displayTitle` и `--kit-title-*`.
3. **Растровые детали — `art.ts`.** Одна деталь — один файл на все окна: рамка 9-slice, полосы
   (`bar-track`, `bar-fill`, срезы `--kit-bar-*`), фактура полей (`page-texture`). Числа
   срезов — переменными в `theme.css` рядом с цветами. Значки — раздел «Иконки» ниже. Кнопка с
   фактурой — одна серая картинка `button-base` на все цвета (раздел «Растровая кнопка» ниже).
4. **Листы компонентов — `COMPONENTS`.** Только там, где общего листа мало: плашки верхней
   панели и меню, карточки магазина, ячейки дней, первые места рейтинга. Ключ — имя компонента из
   таблицы ниже. Кит кладёт `COMMON` **после** листа компонента: правило, уточняющее общее,
   пишется на одну часть селектора длиннее (`.dialog-backdrop .dialog` вместо `.dialog`).
5. **Галерея** — после каждой правки смотреть только те виды, которые она затронула, частичным
   прогоном (`--only`, `--size`, секунды); все виды в трёх размерах — один раз в конце (ниже).
6. **Готовность** — `npm run test:unit`, затем строгие режимы (ниже).

## Шапка окна и плашка заголовка
Заголовок любого окна кита стоит посередине окна на всю его ширину, крестик лежит поверх угла и
ширину у заголовка не отнимает (`WINDOW_HEAD_CSS` в `src/shell/skin.ts`, для рамки самой
оболочки — `SHELL_LAYOUT`). С обеих сторон шапка держит одинаковое место под крестик —
`--game-close-zone` в `theme.css` (44px: кнопка кита 40px и её отступ); длинный заголовок
переносится внутри этих полей и под крестик не заходит.

Почему так: у кита шапка — строка `flex` (`.dialog-head{display:flex;gap:12px}`, заголовок
`flex:1` от левого края, крестик `flex:none` справа, `ui-kit/dist/skin-bundles/manyplay/css/*.css`), поэтому
плашка или лента заголовка начиналась у левого поля и кончалась перед крестиком — сдвинута на
полкрестика от середины. `closePosition: 'corner-out'` выносит крестик за угол рамки и тоже
оставляет заголовок у левого края. Правило оболочки работает при `head-right` и `head-left`;
`corner-out` кит рисует сам.

Плашка (лента) заголовка игры:
- задаётся в `COMMON` на заголовке шапки (`.dialog-head [data-skin-slot=title]`), по центру окна —
  это уже делает оболочка, своё выравнивание не нужно;
- 9-slice (`border-image` с числами срезов в `theme.css`): тянется по ширине текста и не сплющивает
  углы; ширина и поля — от текста, не фиксированные;
- боковые поля плашки симметричны, крестик не заходит на текст (`--game-close-zone`).

Исключение кита: рейтинг на телефоне в ландшафте (высота ≤ 520px) разворачивает шапку в строку
сетки (`display:contents`: заголовок над левой колонкой, вкладки, крестик) — там заголовок стоит
над колонкой подиума, проверка галереи такие шапки пропускает.

## Растровые детали 9-slice
Элемент с `border-image` не может быть меньше суммы своих срезов: сумма верхнего и нижнего
(`border-top/bottom-width`) — не больше его высоты, левого и правого — ширины. Иначе браузер
сжимает углы, и плашка выглядит сплющенной. Самое низкое место в окнах шаблона — ступени подиума
рейтинга (`.lbw-step`): 44, 32 и **20 px** у третьего места (и у всех трёх в ландшафте), значит
срезы плашки подиума по вертикали — не больше 10 px каждый (или отдельная картинка для
`[data-rank="3"]`). Галерея находит такие элементы во всех видах и размерах и падает на них.

## Растровая кнопка: одна серая картинка на все цвета
Кнопки по умолчанию рисуются кодом. Гладкая заливка, градиент, блик, фаска, обводка, тень —
это переменные и правила в `COMMON` (`background`, `box-shadow`, `border-radius`), картинка для
них не нужна. Растровая кнопка оправдана только в двух случаях: у материала есть **фактура**
(дерево, бумага, камень, ткань) или у кнопки **неровный рукотворный контур** (рваный край,
вырезанная доска).

В этих случаях рисуется **одна** картинка в оттенках серого, а цвет каждому виду кнопки даёт код.
Отдельная картинка на каждый цвет не допускается: основная, вторая, кнопка цены, опасная и
выключенная — одна и та же картинка под разным цветом.

**Как нарисовать основу**
- оттенки серого, без оттенка цвета: только объём (свет сверху, тень снизу) и фактура;
- середина — средний серый (около 50 %): он становится чистым цветом вида; светлее — осветляет
  цвет, темнее — затемняет;
- без текста, значков и запечённого цвета; без мягкой тени и свечения вокруг (полупрозрачные
  области красятся в цвет вида) — тень задаётся кодом, `--game-button-shadow`;
- прозрачный фон, контур — альфой картинки: за неровный край ничего не выходит;
- размер 2x от показа (один файл; общее правило файлов скина — [ниже](#файлы-картинок-скина)); высота картинки — не больше двух срезов плюс несколько пикселей середины;
- срезы: углы и края, которые не тянутся, одинаковой толщины со всех сторон или 1–4 числа, как у
  `border-image-slice`. Середина тянется (фактура вдоль неё — тоже), углы и края — нет.

**Как включить**
1. Файл — в `assets/skin/`, ключ `button-base` в `ASSETS` (`src/skin/art.ts`):
   `'button-base': 'button.webp'`. Пока ключа нет, правил нет вовсе и кнопки остаются как были.
2. Числа и цвета — в `src/skin/theme.css`, раздел «Raster buttons»:

| Переменная | Что задаёт |
|---|---|
| `--game-button-slice` | срезы в пикселях картинки, без единиц (`24` или `20 28 24 28`) |
| `--game-button-edge` | те же края на экране (`12px` для картинки 2x) |
| `--game-button-primary` | цвет основной кнопки (`.mp-button--primary`, `.std-action--primary`, кнопки окон кита без варианта) |
| `--game-button-secondary` | вторая кнопка, отмена (`.mp-button--secondary`, `.std-action--secondary`, `data-variant=ghost`) |
| `--game-button-buy` | кнопка цены в магазине (`.iap-buy`) |
| `--game-button-danger` | удалить, выйти (`.mp-button--critical`, `.mp-button--danger`) |
| `--game-button-text` | цвет надписи; для одного вида — `--game-button-<вид>-text` |

Необязательные (в `theme.css` их нет, пока не нужны): `--game-button-blend` — режим наложения
цвета на серую основу (`overlay` по умолчанию; `multiply` — темнее и плотнее, `soft-light` —
мягче); `--game-button-repeat` — середина тянется (`stretch`) или повторяется (`round`);
`--game-button-shadow` — тень по контуру (`0 2px 0 var(--game-shade-strong)`);
`--game-button-hover`, `--game-button-pressed` — яркость при наведении и нажатии (`1.08`, `.92`);
`--game-button-press` — сдвиг при нажатии (`1px`).

Наведение и нажатие делает код (яркость и сдвиг), выключенная кнопка — та же картинка без
насыщенности. Ширина кнопки остаётся такой, какой её задаёт кит: по содержимому или по ряду.
Кнопки-надписи (`.mp-button--text`, `.mp-button--ghost`, `.std-action--text`) и фирменные кнопки
входа плашки не получают.

**Вторая картинка поверх — `button-overlay`.** Необязательный ключ в `ASSETS`: картинка ложится
поверх каждой кнопки и не красится — обод, заклёпки, блик. Те же срезы, что у основы, или свои:
`--game-button-overlay-slice`.

**Что так не сделать**
- Кнопка из двух материалов (деревянная доска в железной оправе): один цвет красит всю основу.
  Материал, который не должен краситься, — в `button-overlay`.
- Разный орнамент или разная форма у разных видов — это разные картинки; механизм рассчитан на
  одну. Такой вид рисуется своим правилом в `COMMON` со своей картинкой (и она тоже серая, если
  у неё несколько цветов).
- Кнопка ниже или уже суммы срезов: углы сожмутся (раздел «Растровые детали 9-slice» выше).

**Проверка в галерее.** Вид `buttons` показывает все виды кнопок в двух ширинах — по содержимому
и растянутую: `… node tests/skin-gallery.mjs --only buttons --size 1280x720`, снимок
`buttons-1280x720.png`. Смотреть: фактура видна на каждом цвете, цвета соответствуют переменным,
края чистые, углы у узкой и широкой кнопки одинаковые. Те же кнопки в окнах — виды `shop`,
`confirm`, `settings`, `game-window`. Сам механизм галерея проверяет при каждом прогоне с видом
`buttons` на тестовой серой картинке, которую делает сам тест (снимки `buttons-tinted-*.png`):
одна картинка на все виды, цвета на экране равны переменным, края узкой и широкой кнопки
совпадают по пикселям, за контуром ничего нет, верхняя картинка не окрашена.

Как это устроено (`src/shell/button-tint.ts`): три слоя с одним и тем же 9-slice. Сама кнопка —
серая картинка (`border-image`); `::before` — силуэт той же картинки цветом вида, наложенный на неё
(`mix-blend-mode`); `::after` — верхняя картинка. Силуэт в Chromium и Safari — цвет под 9-slice
маской (`-webkit-mask-box-image`, `mask-border`); в Firefox такой маски нет, там силуэт — тень
картинки без размытия (`drop-shadow`). Проверено в Chromium 141, Firefox 142 и WebKit 26
(`TINT_ENGINES=chromium,firefox,webkit`).

## Картинки предметов и предложений
Не значки скина, а данные игры: `ITEMS` и `OFFERS` в `src/skin/art.ts` (файл в `assets/skin/` или
`icon:<ключ кита>`). Оболочка делает из них ассеты скина `icon-<id предмета>` и
`offer-<ключ предложения>`, их рисуют окно награды, магазин, награды дня и капсула валюты.
Подробно — [inventory-and-currency.md](../services/inventory-and-currency.md#картинка-и-название-предмета).
Как и любой файл скина, картинка предмета скачивается до включения скина и считается в
`SKIN_WEIGHT_LIMIT`; одна битая — скин не включается.

## Фон сцены и панели
Фон сцены — один слой под всей игрой, от края до края экрана во всех трёх размерах: под
топбаром, колонками HUD, экраном и нижним меню. Панели его не режут: у них нет своей полосы.
- **Картинка — `src/skin/art.ts`, ключ `scene`** (файл в `assets/skin/`): `scene: 'scene.webp'`.
  Обвязка (`SCENE_CSS` в `src/shell/skin.ts`) кладёт её фоном `.mpg-shell` с `cover`: картинка
  заполняет игру целиком и обрезается по краям. Что остаётся в кадре в любом размере — точка
  `--game-scene-position` в `theme.css` (`50% 50%` — середина; `50% 30%` — выше середины).
  Картинку рисовать с запасом по краям: в портрете 390×844 и ландшафте 844×390 видны разные её части.
- **Свой фон маршрута** (игровой экран, второй раздел лобби) — ключ `scene-<маршрут>`:
  `'scene-game': 'scene-game.webp'`. На этом маршруте он заменяет `scene`, всё остальное так же.
- **Без картинки** — стоковый градиент из переменных `--mp-bg-*` (`theme.css`, раздел «Palette»).
- **Полосы панелей — переменные `theme.css`:** `--game-bar-top` (топбар и полоса безопасной зоны
  над ним), `--game-bar-bottom` (нижнее меню и полоса под ним), `--game-bar-line` (линия на их
  границе). В шаблоне все три `transparent` — это осознанный отход от стока (у ManyPlay полосы
  цвета панели, `--mp-card-background`). Сделать полосу снова непрозрачной — задать ей цвет.
  Колонки HUD прозрачны и в стоке.
- **Экраны игры** не рисуют свою карточку, рамку или поля вокруг сцены и свой фон: содержимое
  стоит прямо на фоне сцены ([add-a-screen.md](add-a-screen.md)).
- **Читаемость.** Под панелями может оказаться любая картинка, поэтому голый текст и значки на
  фон не ставятся: у капсул топбара, плиток HUD и пунктов нижнего меню своя заливка
  (`--mp-card-background`, рамка `--mp-card-line`), подпись приподнятой кнопки меню — на своей
  плашке, заголовок главного экрана — на плашке того же вида (`.hero-title`, `src/screens/ui.ts`).
  Новый текст на экране — тоже на плашке или в кнопке.
- Проверка — вид `home` галереи (без нижнего меню, как поставляется шаблон) и `home-menu`
  (нижнее меню с тремя тестовыми пунктами — для игры, у которой оно есть).

Как это устроено (rc.30): фон сцены у кита — фон `.mpg-shell` (`--mp-shell-background`), сетка
шелла занимает весь экран, строки топбара и нижнего меню лежат внутри неё, поэтому прозрачная
полоса показывает тот же фон. Полосы в стоке залиты `var(--mp-night)` (лист `shell`: топбар,
полосы безопасной зоны; лист `bottomMenu`: `.bottommenu`); `scripts/stock-colors.mjs` (`BANDS`)
повторяет эти правила с `--game-bar-*` и падает, если кит их переименует. Пустое нижнее меню
скрыто правилом обвязки, строка сетки кита (`auto`) тогда сворачивается в 0.

## Стартовый экран
Что видит игрок от открытия страницы до главного экрана — без ручной работы в игре:
1. **Первый кадр — `index.html`, `#boot-loader`.** Нейтральная тонкая полоса загрузки на
   нейтральном тёмном фоне: только встроенный CSS, ни одного запроса, ни цвета скина, ни
   картинок, ни бренда. Её видно, пока грузятся SDK и код игры. Заголовок вкладки и
   `<html lang>` пишет сборка (`scripts/build.mjs`): имя проекта из `project.json` (`name`), без
   него — `shell.title` базовой локали (`DEFAULT_LOCALE`, `src/boot/strings.ts`).
2. **Экран загрузки игры — компонент кита `preloader` в `#preloader`.** `src/boot/start.ts`
   монтирует его только **после** того, как скин игры включён, поэтому стоковых цветов он не
   показывает ни кадра: цвета — переменные `theme.css` (через `stock-colors.ts`), фон — картинка
   `scene` из `art.ts` под затемнением цвета страницы (без картинки — цвет страницы
   `--mp-window-background`), название — `shell.title` локали или имя проекта. Стоковый знак
   ManyPlay скрыт; свой знак — ключ `icon-brand-mark` в `ASSETS`.
3. **Смена без мигания.** Полоса `#boot-loader` убирается, только когда экран загрузки игры уже
   нарисован (кадр после монтирования). Ошибка до запуска (нет SDK, нет `platform.json`) убирает
   полосу и показывает текст ошибки; ошибка запуска остаётся на экране загрузки с «Повторить».

Чего не делать: не вписывать в `index.html` цвета, название или картинки игры — первый кадр
нейтральный, всё своё игра показывает на экране загрузки через `theme.css` и `scene`.

Проверка: `tests/skin-readiness.test.mjs` падает, если в `index.html` нет `#boot-loader` со
встроенным стилем, есть стоковый цвет, слово ManyPlay или запрос раньше входного скрипта;
`tests/build/bundle.test.mjs` — заголовок и язык собранной страницы; `tests/browser-startup.mjs` на
медленной сети в трёх размерах снимает `boot/first-paint`, `boot/sdk-loading`, `boot/game-loader`,
`boot/home` и падает, если первый кадр не нейтральный, если экран загрузки нарисован без скина
игры или если полоса исчезла раньше, чем он появился.

## Иконки
Кит рисует значок по ключу `icon-<имя>` скина: значение — файл (`coins.png`) или вырезка из листа
`файл#sprite=x,y,ширина,высота,ширинаЛиста,высотаЛиста` (SVG `<image>`, перекрасить переменными
нельзя). Игра задаёт ключи поверх ManyPlay; ключ, которого игра не задала, остаётся стоковым. Три
способа, их можно смешивать — побеждает более поздний:
1. **Перекрашенный стоковый атлас — минимум для любой игры.** После `theme.css`:
   `node scripts/skin-icons.mjs`. Скрипт берёт атласы ManyPlay (196 ключей) из SDK в `vendor/`
   (`scripts/stock-skin.mjs`: три WebP без потерь в `ui-kit/skins/manyplay` или один PNG пакета
   `skin-manyplay` в старых SDK), пишет PNG на каждый атлас — `assets/skin/icons-recolored.png`
   для одного, `icons-recolored-<small|medium|large>.png` для трёх — и направляет на них все
   стоковые ключи с теми же координатами (`src/skin/icons.ts`). Перекрас — по пикселю в OKLCH: тон поворачивается, насыщенность
   и светлота сдвигаются так же, как сдвинулись ближайшие по тону и светлоте цвета палитры
   (`--mp-card-accent`, `--mp-card-gold`, `--mp-gold-edge`, `--mp-chest-*`, `--mp-wood`,
   `--mp-card-success`/`-error`/`-info`, `--mp-game-*` и др., список — `ANCHORS` скрипта); светотень
   сохраняется, серые, белые, чёрные и телесные тона не меняются, логотипы входа (Google, Apple,
   Facebook) остаются фирменными. Пока эти цвета стоковые, скрипт ничего не пишет и удаляет свой
   прежний атлас. После каждой правки палитры — запустить снова.
2. **Свой лист для значков, которые видит игрок.** Нарисовать сетку одинаковых ячеек (PNG,
   слева направо, сверху вниз), положить в `assets/skin/` и:
   `node scripts/skin-icons.mjs --sheet game-icons.png --columns 5 --keys coins,gift,trophy`.
   Без `--keys` порядок ячеек — список `tests/skin-gallery/visible-icons.json` (значки шаблона:
   `brand-mark check clock close coins gift hud-settings lock medal-1 medal-2 medal-3 no-signal
   play retry shop sparkle star trophy user`). Записи листа сильнее перекрашенного атласа и
   сохраняются при его пересборке; остальные ключи остаются перекрашенными.
3. **Отдельные файлы.** В `ASSETS` (`art.ts`) после `...ICONS`: `'icon-coins': 'coins.png'`.
   PNG, WebP, SVG — любой формат, который браузер грузит в `<img>`.

Что проверено в ките (rc.30) и чего он требует:
- значение — путь от `assets/skin/` или `http(s)`-адрес; `data:` и ключи не из `[a-z0-9_-]`
  отклоняются (`UI_SKIN_INVALID`); `#sprite=` — только шесть целых чисел, иначе фрагмент
  игнорируется и показывается весь файл;
- формат, размер и происхождение файла кит не ограничивает (SVG, PNG 4096×4096, другой адрес без
  CORS включаются); ограничение — вес скина (`SKIN_WEIGHT_LIMIT`; перекрашенный атлас ≈1 МБ);
- все файлы скина загружаются до включения, лист с разными `#sprite` — одним запросом; один
  недоступный файл — скин не включается (`UI_SKIN_ASSET_LOAD_FAILED`), игра остаётся стоковой;
- если игра задала все стоковые ключи (как делает перекрас), стоковый атлас (1,6 МБ) больше не
  скачивается;
- `star` в шаблоне показывает `rating-star` (у ManyPlay `star` — коробка): перекрас и лист для
  `rating-star` действуют и на `star`; свой `icon-star` (лист, файл) отменяет эту замену.

## Файлы картинок скина
Картинка скина в `assets/skin/` — на выбор:
- один файл (`scene.webp`, `button.webp`, `coins.png`) размером не больше двойного размера показа;
- пара: нарисовать только `<имя>-2x.<ext>` (стороны чётные), `<имя>.<ext>` делает `npm run assets` —
  руками 1x не создавать и не править
  ([рецепт](add-art-and-sound.md#картинки-только-2x-остальное--командой)).

Один файл без `-2x` в `assets/skin/` — не ошибка. Если `-2x` есть, `npm run check` проверяет пару.

## Проверка
- Галерея (после `npm run build`, без сети):
  `PLAYWRIGHT=/path/to/node_modules/playwright SHOTS=tmp/shots node tests/skin-gallery.mjs`.
  Полный прогон — все виды в 390×844, 844×390 и 1280×720; несколько страниц рисуют одновременно
  (по умолчанию до 4, не больше числа процессоров; `--jobs <n>` или `JOBS`). Вид снимается, когда
  он готов, без фиксированных пауз: запросы завершены, шрифты загружены, переходы закончились,
  страница не меняется три кадра подряд. На шаблоне полный прогон — около 20 с.
  Снимки `tmp/shots/gallery/<вид>-<ширина>x<высота>.png`, отчёт `report.json`. Каждый вид рисуется
  дважды — со стоком и со скином игры; отчёт «сток ещё виден» перечисляет элементы, у которых цвет
  текста, фона, рамки, тени или заливки равен стоковому, все показанные значки и стоковые среди
  них, виды без отличий. По умолчанию это отчёт; `SKIN_STRICT=1` — провал при любом остатке.
  Значок, которого нет в `tests/skin-gallery/visible-icons.json`, — провал в любом режиме
  (дописать его туда; картинки предметов `ITEMS` в этот список не входят).
  Тоже провал в любом режиме (`checks` в `gallery.js`): элемент 9-slice меньше суммы срезов;
  заголовок окна не посередине окна или под крестиком; плитка окна награды без картинки предмета из
  `ITEMS` (вместо неё значок категории кита) или с названием поверх картинки (плитка в фокусе);
  в профиле строка с id, кодом языка или прочерком, подписи и значения не в двух колонках;
  открыто окно или слой, а затемнение не равно окну браузера (±1 px) или топбар не под ним; окно
  игры не диалог кита, без заголовка, кнопок кита или с содержимым вне рамки
  ([game-windows.md](game-windows.md)).
- **Как работать с галереей.** Правка стиля → `npm run build` → частичный прогон видов, которые
  правка затронула → посмотреть снимки → следующая правка. Полную строгую галерею не запускать
  после каждой правки: она нужна один раз, перед завершением работы.
  - Частичный прогон: `… node tests/skin-gallery.mjs --only shop,daily --size 844x390` (то же
    переменными: `VIEWS=shop,daily SIZES=844x390`). `--only` — виды через запятую (имена — из
    таблицы выше; неизвестное имя — ошибка со списком видов), `--size` — размеры через запятую;
    можно задать только одно из двух. Проверки и `SKIN_STRICT=1` действуют на то, что нарисовано;
    снимки выбранных видов заменяются, отчёт пишется в `report-partial.json` (полный
    `report.json` не трогается).
  - Частичный прогон приёмкой не считается и сам об этом говорит: первая строка —
    `PARTIAL RUN, not the acceptance: …`, последняя — `PARTIAL RUN, not the acceptance (…)` или
    `FAILED (partial run)`, слова `PASS` в нём нет; с `SKIN_STRICT=1` код выхода никогда не 0
    (2 — замечаний нет, 1 — есть).
  - Приёмка — одна команда, без `--only`, `--size`, `VIEWS`, `SIZES`:
    `PLAYWRIGHT=… SKIN_STRICT=1 node tests/skin-gallery.mjs`, последняя строка `PASS`, код 0.
  - Общие правки (`theme.css`, `COMMON`) затрагивают все виды: смотреть два-три характерных
    (`home`, `shop`, `popup`) в одном размере, остальное покажет полный прогон в конце.
  - Галерея показывает `dist/`: если `src/` новее сборки, прогон начинается с предупреждения
    `WARNING: src/ changed after the last build…` — сначала `npm run build`.
- `node --test tests/skin-readiness.test.mjs`: все цветовые входы стока есть в `theme.css`,
  производные на `:host` не заданы; файлы из `art.ts` есть, всё в `assets/skin/` объявлено и
  используется; имена шрифтов совпадают с `FONTS`; в листах нет запрещённого (ниже); вес
  `theme.css` + листы + `assets/skin/` ≤ `SKIN_WEIGHT_LIMIT` (2 МБ); перечисляет значки из
  `visible-icons.json`, которые ещё берутся из стокового атласа. `SKIN_STRICT=1` — ещё и ни одна
  переменная `theme.css` не рендерит стоковое значение и ни один такой значок не стоковый.
- После обновления кита: `node --test tests/stock-colors.test.mjs`; при расхождении —
  `node scripts/stock-colors.mjs` (новый литерал получает имя в `NAMES` скрипта и строку в
  `theme.css`).

## Лимиты
- Вес скина — `SKIN_WEIGHT_LIMIT` в `src/skin/index.ts`. Кит скачивает **все** объявленные
  картинки до включения скина; одна битая — скин не включается.
- Шрифты: два семейства, латиница и кириллица отдельными файлами (`unicodeRange`).
- Картинка не больше двойного размера показа; свои значки — одним листом.
- Лист компонента — короткие правки (ориентир 2–3 КБ), не новая раскладка окна.

## Чего не делать
- Цвета, радиусы, шрифты в листах — только `var(--…)`; литералы — только в `theme.css`.
- Не задавать в `theme.css` на `:host` то, что сток выводит из `--mp-card-*` (`STOCK_DERIVED`).
- Крючки — только `data-part` и базовые классы кита; без `!important`, `data-testid`,
  `nth-child`, `:has()` по содержимому, удвоения классов.
- Не задавать размеры и положение окон, условий по конкретной ширине в пикселях: раскладка — кита.
- Не рисовать текст на картинках: заголовки и надписи — текстом.
- Не объявлять картинки, на которые никто не ссылается; не делать деталь под одно окно.
- Не рисовать кнопку отдельной картинкой на каждый цвет: одна серая основа, цвета — переменными.
- Не править `src/shell/stock-colors.ts` руками и не подключать ManyPlay вторым слоем.

## Что переменными не перекрашивается
- Значки: весь набор ManyPlay — один цветной PNG-атлас, кит рисует его через SVG `<image>`,
  `mask`/`currentColor` неприменимы. Цвет даёт перекрас атласа скриптом (раздел «Иконки»); чёрные
  и белые значки (`check`, `lock`, медали, `sparkle`…) перекрас не меняет — их заменяет свой лист.
- Окна ManyPlay ID (вход, аккаунт) — фиксированы китом (вид галереи `login` — без отчёта о стоке).
- Искры вокруг картинки в окне награды: у кита это значок `sparkle` атласа ManyPlay — чёрная
  растровая вырезка, а цвет по тону (`.mp-sparkle--gold path{fill}`) рассчитан на SVG-контур,
  которого нет; под любым скином искры были чёрными. Оболочка рисует их сама четырёхлучевой
  звездой цветом тона: `--mp-gold`, `--mp-violet-text`, `--mp-text` (`SPARKLE_CSS`); свой
  `icon-sparkle` на них не действует. Медали рейтинга (`medal-*`) — такие же чёрные вырезки:
  их заменяет свой лист значков.
- Тестовый плеер рекламы кита (`fake-ads`) — цвета во встроенных стилях; в шаблоне рекламы нет.

## Не проверено
- Шаблоны раскладки окон (`windows`) и `assetVariants` в шаблоне не применялись.
- Окна, которых в шаблоне нет (карта уровней, задания, предложения), в галерею не входят:
  добавить их в `tests/skin-gallery/gallery.js`, когда игра их покажет. Окна игры (результат,
  пауза, поражение) — вид `game-window` с тестовым содержимым; своё содержимое игры — добавить
  вид по его образцу (`LAYERS` в `gallery.js`).
