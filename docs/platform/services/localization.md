# Локализация

Весь видимый текст — по ключам: `ctx.t(key, params)` на экранах, `sdk.l10n.t` в оболочке.
Параметры — `{name}`.

## Один файл текстов
Все тексты игры — в записи `localization/strings`, в том виде, в каком её принимает сервис:
дерево на язык (`screen.home.play` → `{ "en": { "screen": { "home": { "play": "Play" } } } }`).
Файл записи — `configs/remote/localization/strings.json`; его и заливают. Больше тексты нигде не
повторяются: встроенные строки (тексты до и без чтения записи) — это та же запись, её ветку
базового языка `src/boot/strings.ts` импортирует при сборке и регистрирует в SDK для своих
пространств `shell.*` (оболочка) и `screen.*` (экраны). Опубликованная запись переопределяет их
по ключам и добавляет языки.

Запись пишут частями: `configs/remote/localization/strings/<часть>.json`, каждая — той же схемы
(`{ "<язык>": { … дерево … } }`). В шаблоне это `shell.json`, `screens.json` и `services.json`
(`item.*`, `offer.*`, `levels.*`… — ключи, которые называют записи сервисов). Свою часть
заводит каждый, кто добавляет тексты: файлы разные — правки не сталкиваются. `npm run strings`
(`scripts/strings.mjs`) склеивает части по имени файла в `strings.json`; его же вызывают
`npm run build`, `npm run typecheck` и `npm run test:unit`. Один ключ с разным текстом в двух
частях — ошибка с именами обоих файлов. `strings.json` при частях руками не правят: он
перезаписывается. Без каталога `strings/` запись — один файл, который правят прямо.

Название игры — ключ `shell.title` (в `strings/shell.json`, в ветке каждого языка): его показывают
главный экран, экран загрузки и оболочка. Заголовок вкладки браузера берётся из названия
приложения на платформе (`project.json`, подставляет `npm run build`), а без него — из `shell.title`.

## Один язык на всю игру
Экраны игры и все окна кита (награда, настройки, магазин, топбар) говорят на одном языке:
**языке игрока, если игра его опубликовала, иначе на базовом** (`en`, `DEFAULT_LOCALE`).
Языки игры — **`LOCALES` в `src/screens/index.ts`**: базовый и каждый переведённый и
опубликованный (`localization/locales` со `status: "published"` и ветка в `localization/strings`).
`src/boot/start.ts` передаёт их в SDK (`l10n.supported`, `gameLocales()`); SDK берёт первый
подходящий из: выбор игрока в настройках → языки браузера → `defaultLocale` записи
`localization/locales` (иначе базовый). Тот же язык получают окна кита (`lang` оболочки),
страница (`<html lang>`) и список языков в настройках.

Почему было иначе: core l10n считает языком игры и каждый язык, на котором модуль регистрирует
свои строки, а модуль UI Kit регистрирует `en` и `ru`
(`vendor/@manygamescorp/ui-kit/dist/module.js:37`, `dist/strings.js:19-22`; выбор —
`available()` в core `l10n.ts`). Браузер с русским получал `ru`: строки игры падали на `en`
(русских нет), а окна кита брали свои русские тексты — «Награда получена!» рядом с «Level complete».
Ограничение `supported` это закрывает.

Новый язык: тег в `LOCALES`, в записи `localization/locales` (`published`) и ветка
`localization/strings` со всеми ключами базового языка (ветку удобно держать своей частью,
`strings/<тег>.json`). `tests/strings.test.mjs` сверяет `LOCALES` с образцами в
`configs/remote/localization/` и называет ключи, которых языку не хватает. Тег в `LOCALES` без опубликованной записи — ошибка: кит покажет
свои тексты на этом языке, а игра — базовые.

## Записи
| scope / key | Файл |
|---|---|
| `localization` / `strings` — `{ en: { … } }` | `configs/remote/localization/strings.json` (склеен из `strings/*.json`) |
| `localization` / `locales` — `defaultLocale`, языки | `configs/remote/localization/locales.json` |

## Где подключено
Встроенные строки регистрирует `src/boot/strings.ts` — из ветки базового языка записи:
```ts
    if (typeof tree === 'object') l10n.registerDefaults(ns, { [DEFAULT_LOCALE]: tree });
```
`tests/strings.test.mjs` проверяет то, что ещё может разойтись: `strings.json` склеен из частей;
каждый ключ `shell.*`/`screen.*` из кода есть в записи для базового языка, а лишних нет; есть
`shell.title`; у каждого языка из `LOCALES` есть все ключи. Сообщение называет ключи и файл,
который править.

## Как проверить
На экранах нет «сырых» ключей; изменённая в записи строка видна после перезапуска.
`tests/browser-startup.mjs` открывает игру с русским браузером: `<html lang="en">` и окно настроек
без русского текста (кроме названия языка «Русский», если он опубликован).
