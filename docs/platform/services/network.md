# Сеть: без опросов

Изменения состояния приходят событиями, а не повторными запросами. Ни один код игры не
перечитывает состояние в цикле, по таймеру или «на всякий случай».

## Что делает шаблон
| Что | Когда читается | Как узнаёт об изменениях |
|---|---|---|
| Конфиги | при запуске: снимок записей приложения (SDK, один раз); дальше — только точечно по нужде: конкретный scope или запись, один раз за сессию (диапазон уровней — модулем `levels` при первом уровне из него, следующий — заранее в фоне) | команду перезагрузки записей (`configs.reload`) присылает сервер через `realtime` |
| Локализация | при запуске (`l10n.refresh: 'start-only'` в `src/boot/start.ts`, без 30-минутного опроса SDK) | новые тексты — со следующего запуска |
| Прогресс | один `progress.init` со всеми треками при запуске (`src/boot/progress-state.ts`) | после запуска отправляются только действия (`levelEnd`, `login`); прочитанное состояние меняется по их принятию |
| Инвентарь | при запуске (модуль inventory) | `realtime` → `inventory.balance.changed` → `inventory:items:granted` → окно награды и топбар |
| Облачное сохранение | никогда, пока игра сама не вызовет `loadSave`/`save` | — |

Модуль `realtime` (`@manygamescorp/mod-realtime`) входит в набор модулей шаблона: одно
соединение на сессию (WebSocket `/v1/realtime/ws`; если его нет — поток `/v1/realtime/stream`).
Без него сервер ничего не присылает: награда появляется только после следующего чтения
инвентаря — шаблон делает одно такое чтение при смене экрана после ожидаемой выдачи
(`src/boot/grants.ts`), а изменения конфигов становятся видны со следующего запуска.

## Что игре нельзя
- Перечитывать прогресс, инвентарь, конфиги или сохранение после действия, в цикле, по
  `setInterval`/`setTimeout`, при смене экрана, старте уровня или открытии окна.
- Ждать награду после `endLevel`: результат показывается по ответу (`verified`, `stars`), награду
  покажет окно награды, когда она придёт.
- Писать облачное сохранение на каждом ходу; сохранение — только если игре нужно продолжить
  уровень после перезагрузки, и тогда редко (пауза, выход из уровня).
- Загружать записи конфигов целыми разделами «чтобы обновить»: только нужная запись и один раз.

## Что делает SDK сам
Ядро SDK раз в 5 минут перечитывает снимок конфигов, пока вкладка видима (`configs:refresh`
в `@manygamescorp/core`, настройки отключения в rc.30 нет). Модуль `realtime` держит соединение
и шлёт служебный пульс. Это поведение SDK, а не игры.

## Как проверить
`tests/browser-startup.mjs` считает запросы к API за запуск и 10 с простоя и падает, если путь
запрошен больше, чем разрешено (`BUDGET`: `progress/me/init` — 1, `game-states/me` — 0, …);
за весь прогон — один `progress/me/init` и ни одного `game-states`.
