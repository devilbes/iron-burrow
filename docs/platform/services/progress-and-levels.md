# Уровни, прогресс, сохранение, аналитика

Готовые сервисы уровня для игры — `GamePorts` (`src/modules/game/index.ts`), реализация —
`src/boot/game-ports.ts`. Экран получает их как `ctx.game`. **Заглушка шаблона их не вызывает**:
их вызывает цикл уровня настоящей игры. Правила сети для всех них — [network.md](network.md).

| Метод | Что делает | Запросы |
|---|---|---|
| `currentLevel()` | следующий уровень: число пройденных шагов трека `progress_main` + 1; после `last` набора — последний | нет: прогресс прочитан один раз при запуске |
| `level(n)` | `{ n, last, id, entry }`: `entry` — элемент `entries[]` записи уровней (числа игры, JSON — игра сама сужает тип), `id` — id уровня (ключ шага прогресса), `last` — последний уровень набора (`null` — набор без конца) | модуль `levels`: оглавление и диапазон — один раз за сессию, следующий диапазон он подгружает заранее сам |
| `beginAttempt(level)` | попытка с сидом от сервера (`progress.beginAttempt`) → `{ seed }`; сид и время начала — в памяти | одна |
| `endLevel(level, won, { moves, score })` | `levelEnd` с сидом и длительностью попытки → `{ verified, stars }` сразу по ответу сервера | одна |
| `loadSave()` / `save(state)` / `save(null)` | облачное сохранение игры — **по умолчанию выключено**, см. ниже | только когда игра их вызывает |
| `track(event, params)` | `sdk.analytics.sendEvent`, никогда не бросает | — |

Игре не нужны ни SDK, ни `src/boot/ids.ts`: данные уровня — `level(n).entry`, сид попытки —
результат `beginAttempt`.

## Конец уровня и награда
Сервер проверяет конец уровня по сиду и границам записи уровня (`server`: `moves`,
`durationMs`, `score`) и отвечает сразу: `verified` и `stars`. Экран результата показывается по
этому ответу. Награду шага `progress_main` сервер выдаёт сам и позже ответа (202) — клиент суммы
не считает, не отправляет и **не ждёт**. Выдача приходит событием: модуль `realtime` получает от
сервера `inventory.balance.changed`, inventory перечитывает себя и шлёт на шину
`inventory:items:granted`; по нему триггер `reward-on-grant` (`ui.windows/main`) открывает окно
награды, а капсула монет в топбаре обновляется. Повтор уже выигранного уровня награды не даёт.

Без модуля `realtime` клиент о выдаче не узнаёт ничем, кроме запроса. Тогда шаблон делает ровно
одно чтение инвентаря при следующей смене экрана после ожидаемой выдачи (`src/boot/grants.ts`,
`settle` — из `src/shell/router.ts`): игрок возвращается на карту — окно награды появляется. Если
выдача на сервере ещё не прошла к этому моменту, она станет видна при следующем чтении инвентаря.
Ожиданий, повторов и таймеров нет.

## Прогресс: один раз за сессию
Все треки игры (`PROGRESS` в `ids.ts`: `progress_main`, `reward_daily`) читаются одним
`progress.init` при запуске (`src/boot/progress-state.ts`). Ответ на `levelEnd` и `login` не
содержит состояния, поэтому после принятого действия шаблон меняет прочитанное состояние сам:
проверенная победа отмечает шаг уровня пройденным (`currentLevel()` → следующий уровень), вход
дня — доступный день. Повторного `init` после уровня нет. Чтение, упавшее по сети, повторяется
при следующем обращении; отказ сервера (трек не опубликован или неверен) остаётся ответом на
всю сессию.

## Попытка и перезагрузка
Сид и время начала попытки живут в памяти. Перезагрузка страницы посреди уровня начинает
уровень заново с новой попыткой — это поведение по умолчанию. Длительность конца уровня
считается от начала попытки; повтор `endLevel` после потерянного ответа отправляет те же факты
с тем же `eventId`.

## Облачное сохранение (по желанию игры)
Уровень берётся из прогресса, поэтому сохранение шаблону не нужно: без вызовов `loadSave`/`save`
запросов к `game-states` нет вовсе. Игра, которой нужно продолжить уровень после перезагрузки,
сама вызывает `save(state)` в выбранные моменты — редко: на паузе и при выходе из уровня, не на
каждом ходу; `loadSave()` при входе в уровень (читает один раз за сессию), `save(null)` — после
конца уровня. Запись идёт с версией; если другое устройство записало раньше, порт перечитывает
версию и пишет ещё раз.

## Записи
| scope / key | Что |
|---|---|
| `levels.main` / `set` | оглавление набора: `first`, `last`, `index[]` |
| `levels.main` / `r_0001_0005` | уровни 1–5: `entries[]` (`id`, `title` и числа уровня — свои у каждой игры) и `server` — границы проверки по уровням и `contentHash` |
| `progress` / `progress_main` | трек `sequence`: шаг на уровень (`level_N`, фильтр `{ set, n, won: true, verified: true }`), `reward`, `claimMode: "auto"` |

Число уровней — `last` записи `levels.main/set` из снимка конфигов, прочитанного при запуске:
```ts
    const last = sdk.configs?.get<{ last?: unknown }>(LEVEL_SET_RECORD.scope, LEVEL_SET_RECORD.key)?.last;
```

Диапазоны уровней загружает модуль `levels` (`levels.open('main')` → `get(n)`): запись диапазона —
один раз, дальше из памяти и хранилища браузера (после перезагрузки — одна проверка с
`If-None-Match`). Следующий диапазон он подгружает заранее в фоне. Размер и подгрузка — настройки
модуля `progress` в `platform.json` (`sdk.modules[id=progress].settings`), не код: `chunkSize` —
сколько уровней в одной загрузке, `prefetchDepth` — на сколько загрузок вперёд (0 — без
подгрузки), `cacheMaxBytes` — объём кеша.

## Как проверить
Тестами `tests/game-ports.test.mjs` (один `progress.init`, записи уровней один раз, конец уровня
без ожидания награды, сохранение только по вызову игры) и `tests/grants.test.mjs`; в игре —
победа на уровне 1 → окно награды шага `level_1`, `currentLevel()` → 2 без новых запросов к
прогрессу.
