# Топбар, HUD, меню и окна сервисов

| Зона | Что в ней | Чем задаётся |
|---|---|---|
| Топбар, слева | профиль, затем счётчики игры (предметы, уровень) | список `TOP_BAR` в `src/screens/index.ts` |
| Топбар, справа | только настройки | `src/shell/zones.ts` |
| HUD, левая колонка | активности: ежедневные награды, лидерборд, события, задания | список `HUD`, `kind: 'activity'` |
| HUD, правая колонка | деньги: магазин, офферы, акции | список `HUD`, `kind: 'money'` |
| Нижнее меню | опционально: по умолчанию нет и места не занимает; пункты — список `MENU` | `src/screens/index.ts` |

Инвентаря на экране нет. На игровых маршрутах (`GAMEPLAY` в `src/screens/index.ts`) нет HUD и
меню, в топбаре — только счётчики. Плитки HUD — без подписи: имя остаётся доступным именем кнопки.
Вид окон и зон — скин ManyPlay с темой игры ([recipes/custom-window-skin.md](../recipes/custom-window-skin.md)).

Панели — прозрачные слои поверх общего фона сцены: у топбара, нижнего меню и колонок HUD нет
своей полосы (`--game-bar-*` в `theme.css`, по умолчанию `transparent`), вид есть только у их
элементов — капсул, плиток, кнопок. Фон сцены один на всю игру, от края до края, под панелями
и экранами ([фон сцены и панели](../recipes/custom-window-skin.md#фон-сцены-и-панели)).

## HUD: одно место — список `HUD`
Все плитки HUD игры перечислены в `HUD` (`src/screens/index.ts`), и плитки модулей, и свои;
`src/shell/` для этого не меняется ([рецепт](../recipes/add-a-hud-entry.md)). Шаблон — три плитки:
```ts
export const HUD: readonly HudEntry[] = [
  { id: 'daily-rewards', kind: 'activity' },
  { id: 'leaderboards', kind: 'activity' },
  { id: 'shop', kind: 'money' },
];
```
- **Сторона — по смыслу**, не выбирается: `activity` — левая колонка, `money` — правая. Порядок в
  колонке — порядок в списке; он же приоритет при нехватке места.
- **Плитка модуля** — `id` плитки, которую модуль регистрирует сам: `daily-rewards`,
  `leaderboards`, `shop` (ещё есть `offers`, `progress`). Только `id`, `kind` и при нужде `status`
  (видимость); картинка, имя и окно — модуля. Плитка модуля, которой нет в `HUD`, не видна
  (`inventory`, `profile`, `settings` в `HUD` не допускаются).
- **Своя плитка** — любой другой `id`: `icon` (ключ иконки скина: `star`, `calendar`, `quest`,
  `trophy`… или id предмета из `ITEMS`), `label` (ключ строки — доступное имя), что открывает:
  - окно кита — по умолчанию: нажатие сообщает элемент `hud:<id>`, триггер записи
    `ui.windows/main` открывает окно (`{ "on": { "element": "hud:event" }, "do": [{ "module": "progress", "action": "quests" }] }`);
  - экран игры — `open: { route: 'event' }`; свой код — `open: { run: (ctx) => … }`;
  - `status: { on: [события шины], read(ctx) }` — значок (`badge: 'dot' | число`), отсчёт
    (`endsAt`, мс) и видимость (`visible: false` — плитки нет: за ней ничего нет); читается при
    старте, для нового игрока и на каждое событие из `on` (без опросов и таймеров).
- **Плитка оффера** — `offer: true`, `kind: 'money'`, ниже.

Регистрирует свои плитки и считает статусы `src/shell/hud.ts`; правила стороны, порядка и проверки
объявления — `src/shell/hud-plan.ts`.

## Офферы на HUD
Своего плиточного компонента оффера у кита нет. Есть плитка `offers` модуля iap
(`vendor/@manygamescorp/mod-iap/dist/iap.js`: подарок, справа, отсчёт до ближайшего конца
офферов плейсментов, которые открывает триггер `hud:item:opened {id: offers}`), но она видна и
при пустом плейсменте и всегда с подарком — в `HUD` шаблона её нет. Плитка оффера игры
стоит на реестре HUD кита и делает то же по тому же правилу, плюс:
- плейсмент — из записи, а не из кода: шаг `iap.offer` с `params.placement` в триггере плитки
  `ui.windows/main` (на элемент `hud:<id>` или на `hud:item:opened` с `payload.id`);
- плитка видна, только пока в плейсменте есть доступный оффер; картинка — первого доступного
  оффера из `OFFERS` (`src/skin/art.ts`; без неё — `icon` плитки), отсчёт — до его `endsAt`
  (расписание оффера); пересчёт на `iap:offers:updated`, публикацию записей и конец отсчёта;
- нажатие — окно оффера кита (`limitedOffer`, `src/shell/windows/offer.ts`): этот оффер, цена из
  магазина, покупка через `iap.purchase`, выдача — окном награды.

Сколько офферов — столько плиток с плейсментами: стартовый набор и распродажа — две плитки,
два плейсмента. Плейсмент магазина (`placement_shop`) на HUD не выносить: это плитка `shop`.

## Топбар: список `TOP_BAR`
```ts
export const TOP_BAR: readonly BarResource[] = [
  { kind: 'item', id: CURRENCY, label: 'shell.currency.coins' },
  { kind: 'level' },
];
```
- `item` — количество предмета инвентаря (валюта или любой счётный предмет): `id` — id каталога,
  картинка — его из `ITEMS` (или `icon`), `label` — ключ доступного имени. Счётчики предметов
  рисует оболочка (капсулы валют модуля inventory не показываются), на всех экранах;
- `level` — уровень игрока (сервис профиля, звезда кита, если не задан `icon`).
Порядок — порядок в списке, сразу за профилем. Справа — только настройки.

Нажатие на счётчик предмета и на его «+» открывает магазин — если в `HUD` есть плитка `shop`
(сообщается элемент `hud:shop`, его триггер записи `ui.windows/main` открывает окно магазина).
Своё — полем `open` записи: `{ element: 'hud:offer-gems' }` (другой элемент для триггеров),
`{ route }` или `{ run }`, как у плитки HUD; `open: false` — ничего. Счётчику, которому нечего
открыть (`open: false` или магазина в `HUD` нет), кит «+» не рисует: «+» есть только у капсул
`currency.<предмет>`, такой счётчик регистрируется под id предмета (`counterOpen`, `barCounters`
в `src/shell/hud-plan.ts`).

## Когда не помещается
- **Колонка HUD**: плитки 64×64 в порядке `HUD`; что не помещается по высоте, уходит в прокрутку
  колонки (собственное поведение кита, без полосы прокрутки), колонка не заходит под топбар и за
  край окна. В ландшафте телефона (844×390) в колонке целиком видно 4 плитки (пятая выглядывает
  краем — знак прокрутки), в портрете 390×844 и на 1280×720 — не меньше 6; первые по списку
  видны всегда. Колонки стоят по краям поверх экрана — экраны
  держат поля под них (`src/screens/ui.ts`), поэтому плиток больше 4 на сторону в лобби не
  планировать: важное — первым в списке.
- **Топбар**: счётчик, который не помещается целиком между профилем и настройками, не
  показывается (уходит во второй ряд, он скрыт) — вместе со всеми после него. В портрете 390
  помещаются профиль и два счётчика (монеты с «+» и уровень); третий — только в ландшафте.

## Как проверить
- `npm run test:unit` — `tests/hud.test.mjs`: сторона по смыслу, порядок, что может и чего не
  может запись `ui.hud/layout`, плейсменты и отсчёт плитки оффера, счётчики топбара; готовность —
  у каждой своей плитки и счётчика есть иконка скина и строка (список того, чего нет).
- Галерея скина (`tests/skin-gallery.mjs`): вид `home-hud` — событие, оффер с отсчётом, второй
  ресурс; `home-hud-full` — больше плиток, чем помещается; в 390×844, 844×390, 1280×720 проверяет,
  что у каждой плитки есть картинка и доступное имя, плитки не налезают друг на друга и на
  топбар, стороны совпадают с `kind`, счётчики топбара не обрезаны.

## Нижнее меню
- Пустой `MENU` (как в шаблоне) — панели нет, её строка в раскладке кита сворачивается в 0.
  Главный экран ведёт в игру своей кнопкой «Play»; меню с одной кнопкой «Play» не нужно.
- Пункты добавлять, только если в лобби несколько разделов: `{ id, icon, label, route }`,
  `center: true` — приподнятая кнопка в середине, `order` — порядок. Боковые пункты (до четырёх)
  занимают слоты слева направо, симметрично вокруг середины; слот, занятый модулем, пропускается.
  Подписи — ключи записи `localization/strings`; пункты видны только в лобби, не на `GAMEPLAY`.
- Модуль, настроенный жить в нижнем меню (ежедневные награды с `entry: bottomMenu`), показывает
  панель и при пустом `MENU`: панель скрыта, только пока в ней нет ни одного пункта.
- Настройка `bottomMenu` модуля `ui-kit` (`platform.json`) в шаблоне `true`, и менять её не нужно:
  пустое меню и так не рисуется. `false` выключает зону целиком — кит не берёт в неё ни пункты
  `MENU`, ни модули (модули с запасным местом уходят в HUD). Обойти это из игры нельзя и не надо:
  `platform.json` формирует платформа.

## Окна сервисов
Игра окна сервисов не рисует: она сообщает элемент, а триггеры записи `ui.windows/main`
решают, какое окно открыть. Плитка HUD сообщает `hud:<id>` (и событие `hud:item:opened {id}`):
```ts
    opened: (id) => sdk().ui.elementAction(`hud:${id}`) });
```
Кнопки топбара:
```ts
    deps.topBar.add({ ...spec, contexts: LOBBY, onClick: () => deps.sdk().ui.elementAction(ELEMENTS[element]) },
```
Окна самой игры (результат, пауза, поражение, подтверждение) — `ctx.window.open`, тоже окна кита в
скине игры, затемнение на весь экран; окно награды с ними не встаёт одно поверх другого
([game-windows.md](../recipes/game-windows.md)).

Окна модулей в rc.30 только объявляют себя на шине; стандартные окна UI Kit данными модулей
наполняют презентеры `src/shell/windows/` (магазин, оффер, награды, лидерборд, профиль), окна `ui.*`
(ошибка, настройки, награда) — `src/shell/windows/standard.ts`, окно ManyPlay ID —
`src/shell/windows/account.ts` ([profile-and-settings.md](profile-and-settings.md)). Картинки и
названия предметов во всех этих окнах — [inventory-and-currency.md](inventory-and-currency.md#картинка-и-название-предмета);
шапка окон (заголовок по центру, крестик поверх угла) —
[custom-window-skin.md](../recipes/custom-window-skin.md#шапка-окна-и-плашка-заголовка).

## Записи
| scope / key | Файл |
|---|---|
| `ui.windows` / `main` — триггеры «элемент или событие → окно» | `configs/remote/ui.windows/main.json` |
| `ui.hud` / `layout` — опубликованная подстройка объявленных плиток | `configs/remote/ui.hud/layout.json` |
| настройки UI Kit | `platform.json` → `sdk.modules[id=ui-kit].settings` |

Запись `ui.hud/layout` (кит читает её сам) после `HUD` может только скрыть объявленную плитку
(`visible: false`), показать её сегменту (`filters`), дать значок, имя или картинку. Сторону,
порядок и состав задаёт `HUD`: `slot` и `order` записи для объявленных плиток не действуют,
необъявленные плитки скрыты (`unlisted: hide`). В шаблоне запись пустая.

## Окна по входам
Каждая плитка HUD и кнопка топбара открывает своё окно; портрет и ландшафт — зоны не перекрывают экран.
`tests/browser-startup.mjs` открывает и закрывает все окна, у каждого меряет затемнение (окно
браузера от края до края, топбар под ним, в 1280×720, 844×390, 390×844), нажимает «+» монет
(открывается магазин) и проверяет, что на главном экране нет нижней панели. Вид меню с пунктами — вид `home-menu` галереи скина.
