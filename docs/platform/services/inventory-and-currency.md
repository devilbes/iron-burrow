# Инвентарь и валюта

Одна мягкая валюта — монеты `item_coins`. Балансы хранит сервис inventory; начисляет только
сервер (награды за уровни и дни, покупки, стартовый набор). Капсулу монет в топбаре ставит
оболочка по списку `TOP_BAR` (`src/screens/index.ts`; капсулы валют модуля inventory не
показываются — только объявленные счётчики, [windows-and-hud.md](windows-and-hud.md#топбар-список-top_bar)). Окна инвентаря на экране нет: это внутренний сервис валюты и наград.

**Сегодня монеты только копятся.** Ключ приложения не может публиковать правила обмена
(`inventory.exchange`) и стартовый баланс (`inventory.starter`) — это разделы владельца
приложения ([configs.md](configs.md)). Пока владелец их не опубликовал, стартового баланса нет и
потратить монеты в игре не на что; [recipes/spend-currency.md](../recipes/spend-currency.md) —
как это будет работать, когда платформа это откроет.

## Записи
| Что | Файл |
|---|---|
| сущность каталога `item_coins` (`soft_currency`, `display.titleKey`) | `configs/remote/inventory.catalog/item_coins.json` |
| стартовый баланс `inventory.starter` / `item_coins` (`visibility: 2`; публикует только владелец приложения) | `configs/remote/inventory.starter/item_coins.json` |

Сущность каталога создают в каталоге inventory приложения, а не публикацией в configs.
Стартовый набор, если владелец его опубликовал, выдаётся один раз, при первой инициализации
инвентаря игрока.

## Картинка и название предмета
Одно место для картинок предметов и предложений — **`ITEMS` и `OFFERS` в `src/skin/art.ts`**.
Ключ — id предмета каталога (`itemId` записи `configs/remote/inventory.catalog/<id>.json`) или
ключ предложения (`configs/remote/iap.offers/<key>.json`); значение — файл в `assets/skin/`
(своя картинка игры) или `icon:<ключ>` — значок кита в скине игры (стоковый ManyPlay,
перекрашенный `scripts/skin-icons.mjs`):
```ts
export const ITEMS: Readonly<Record<string, string>> = {
  item_coins: 'icon:coins',          // образец шаблона: стоковая монета
  // item_rewind: 'items/rewind.png', // бустер игры: своя картинка
};
```
Название — `display.titleKey` сущности каталога через локализацию (ключ — в каждой ветке
`localization/strings`, образец: `item.coins.title`). Каталог читается один раз после запуска
(`src/shell/item-catalog.ts`).

Откуда это берут окна (`src/shell/icon-aliases.ts` делает из `ITEMS`/`OFFERS` ассеты скина):
| Окно | Картинка | Название |
|---|---|---|
| награда: большая картинка и плитка | `icon-<id>` (описание строки — `rewardDescribe`, `src/boot/start.ts`) | под картинкой, всегда видно |
| магазин: предметы предложения | `icon-<id>` (кит берёт сам по id) | из каталога (`src/shell/windows/shop.ts`) |
| магазин: картинка предложения | `offer-<key>` (кит берёт сам) | заголовок предложения |
| награды дня | `icon-<id>` награды дня, иначе подарок (`src/shell/windows/daily.ts`) | «День N» |
| капсула валюты в топбаре | кит рисует `icon-coins` для мягкой валюты при любом id; своя картинка `CURRENCY` (`ids.ts`) становится и `icon-coins` | — |

Что видит игрок, если игра забыла:
- нет картинки в `ITEMS` — картинка категории кита: сумка с карточкой для бустера (`item`),
  монета или кристалл для валюты, подарок для прочего; название под ней — какое есть;
- нет названия — «Предмет» / «Item» кита.

`tests/skin-readiness.test.mjs` перечисляет предметы каталога без картинки, со стоковым значком
вместо своей картинки и без названия в записи строк; `SKIN_STRICT=1` на них падает. Галерея
(`tests/skin-gallery.mjs`, вид `reward`) проверяет в трёх размерах, что у плитки награды картинка
из `ITEMS`, а не категории кита, и что название не заходит на картинку.

Почему было иначе (rc.30): окно награды рисует `icon` строки (значок скина, картинка модуля или
ключ ассета игры), иначе — значок категории (`ui-kit/src/services/reward-window.ts:160-167`,
`rewardCategoryIcon`: `bag` для `item`); шаблон давал окну только название (`describe` без `icon`),
и у бустера была стоковая «карточка со звездой». Название кит показывает только всплывающей
плашкой поверх плитки при наведении или фокусе (`features/reward-grid-layout.js`:
`.reward-name{display:none;position:absolute;inset:0}`, `:is(:hover,:focus)` → `flex`), а фон
плашки `--kit-reward-tooltip-bg` задан только во встроенном скине кита
(`ui-kit/dist/skins/manyplay/styles/reward-grid.js`), не в `skin-manyplay`, — текст лежал прямо на
картинке, и курсор, оставшийся над плиткой после нажатия, показывал его сразу. Поля картинок самой
записи каталога (`display.images`, у клиента `display.iconUrl`) шаблон не использует: картинка —
часть скина игры и грузится вместе с ним.

## Где подключено
Баланс в окнах магазина и профиля, например `src/shell/windows/shop.ts`:
```ts
    try { return inventory?.balance(CURRENCY) ?? 0; } catch { return 0; }
```
Названия и картинки предметов во всех окнах — раздел выше.

Инвентарь читается при запуске; дальше о выдачах сообщает сервер: модуль `realtime` получает
`inventory.balance.changed`, inventory перечитывает себя и шлёт `inventory:items:granted` →
окно награды (триггер `reward-on-grant`) и капсула монет в топбаре. Опросов нет; без `realtime`
— одно чтение при смене экрана после ожидаемой выдачи ([network.md](network.md)).
Трата валюты сейчас недоступна (см. выше); как она будет устроена —
[recipes/spend-currency.md](../recipes/spend-currency.md).

## Как проверить
Новый гость: в топбаре баланс монет (стартовый — только если владелец опубликовал
`inventory.starter`); после ежедневной награды баланс растёт без перезагрузки.
