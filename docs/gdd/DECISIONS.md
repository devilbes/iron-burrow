# Журнал решений ГДД (режим «Решай сам»)

Владелец не опрашивался; каждое решение принято по умолчанию с обоснованием. Решения разделов (D-10-NN … D-40-NN) записаны в самих разделах; здесь — сквозные.

| ID | решение | обоснование |
|---|---|---|
| D-00-01 | Таргет web, ориентации portrait 390×844, landscape 844×390, desktop 1440×900, orientation_fixed = false | Владелец не ограничил платформу/ориентацию; поле квадратное 13×13 — полноценно играется в обеих ориентациях (портрет: поле сверху во всю ширину, управление снизу; ландшафт/десктоп: поле по центру, HUD и управление по бокам) |
| D-00-02 | Сеттинг «под землёй»: игрок — танк-бур Burrower, база — Burrow Core, враги — Rustbugs | Название Iron Burrow; уход от чужих IP образца (штаб-орёл, имена, графика) |
| D-00-03 | Поле 13×13 клеток, клетка = 2×2 четверти разрушения | Проверенная читаемая структура жанра; разрушение кирпича по четвертям даёт тактику «проковырять стену» |
| D-00-04 | Стадия = 20 врагов, 3 жизни на стадию, одно попадание в Core — поражение | Длительность стадии 90–180 с под веб-сессию; жизни не переносятся между стадиями — мягче для казуальной аудитории |
| D-00-05 | 30 стадий кампании в 3 главах + бесконечный режим Siege (открывается после стадии 5) | «Полноценная игра, не концепт»: кампания даёт прогрессию и звёзды, Siege — реиграбельность и смысл лидерборда |
| D-00-06 | Валют в MVP нет; мягкая валюта Scrap (гараж-апгрейды, коллекция скинов корпуса, бонусные главы) — следующий этап | Правило экономики: траты для валюты придуманы, но платформа пока не публикует правила обмена и стартовый баланс → первая версия без валюты; твёрдой валюты нет вовсе |
| D-00-07 | Расходуемые предметы — 4 бустера (Bubble Shield, Shockwave, Steel Fortress, Spare Hull) | Механика сама их расходует; их выдают награды уровней, ежедневные награды и продаёт магазин |
| D-00-08 | Стартовый грант 2× каждого бустера — отдельной наградой | Ограничение инвентаря платформы: награды не смешиваются с твёрдой валютой (её нет), грант не должен отклоняться целиком |
| D-00-09 | Продолжение после поражения — только за Spare Hull (1 раз на стадию), без рекламы | Рамки потока: рекламы нет; continue-оффер через расходник и покупку набора |
| D-00-10 | Паки: 0.99 / 1.99 / 4.99 / 9.99 / 19.99 USD | Рыночная лестница цен веб/мобильных казуальных игр (см. knowledge-base/research/monetization.md); значения — в конфигах iap.*, меняются без сборки |
| D-00-11 | Лидерборды: siege_best (неделя) и campaign_score (всё время) | Leaderboards подключается, т.к. механика даёт счёт; еженедельный сброс — свойство доски, без отдельного liveops |
| D-00-12 | Не используются: ads (рамки потока), realtime (нет живого мультиплеера/пушей в MVP), scheduling (beta; недельный цикл даёт доска) | Итоговое решение по сервисам — docs/gdd/services-matrix.md (шаг «Сервисы платформы») |
| D-00-13 | Базовый язык en, languages [en] | Рамки потока; остальные локали — шаг локализации |
| D-00-14 | Палитра холодный сланец/сталь + оранжевая магма + кислотно-зелёный | Аркаде нужен контраст и читаемость на скорости; отличие от типовой тёплой казуалки |
| D-00-15 | Текста идеи кроме полей формы нет — идея восстановлена из названия, жанра и описания образца | Режим «Решай сам»; см. docs/analysis/sample.md |
| D-00-16 | Пометку «с бустерами» в Siege-лидерборде в MVP не делаем | Честность обеспечивают лимиты бустеров на забег (×2 от стадии) и недельный сброс; меньше UI и данных доски |
| D-00-17 | Сведение: префиксы ключей по каталогу (`gen.`, `bal.`, `meta.`, `aud.`, `plat.`) | Единые ссылки AC ↔ разделы |
| D-00-18 | Сведение: настройки — один kv-ключ `settings {v, music, sfx, haptics, motion}`, тумблеры; вибрация только `sdk.device.haptics` | Расхождение 15/20/23; принцип «всё через SDK» |
| D-00-19 | Сведение: бустеры в бою — оптимистично, Spare Hull — после подтверждения | Отклик аркады ≤ 50 ms против серверного подтверждения; Spare Hull не критичен по времени |
| D-00-20 | Сведение: первая сессия через окно стартового набора в лобби (как в 20 и first-session.json) | Правило окон наград (награда крупно); единый путь для сценария QA |
| D-00-21 | Сведение: арена Siege — level-set `siege` модуля progress | Уровни только через progress, не через конфиги `game.*` |
| D-00-22 | Сведение: по отдельному `sim:<id>` на метрику Genre targets | Гейт читает одно число на seed из `run(seed)` |
| D-00-23 | В магазине у Field Kit бейдж Best value (D-16-08) | Ресёрч: Hull Pack дороже за штуку — показываем выгодный пак |
| D-LVL-01 | Шаг уровней: кампания — scope `levels.main` (set + `r_0001_0010`/`r_0011_0020`/`r_0021_0030` по главам), арена Siege — `levels.endless/r_0001_0001`; «level-set campaign/siege» из 30/31 = эти scope | Платформа не разрешает свои имена наборов (`levels.campaign`/`levels.siege`); endless — штатный набор бесконечного режима (docs/levels/BRIEF.md §7) |
| D-LVL-02 | Исходники — файл на стадию в формате ГДД 12 §1; в записи configs `quarters` — массив `[{col,row,mask}]` | Ключи словарей configs не допускают запятую «col,row»; формат ГДД для авторов сохранён, перевод делает `tools/levels/export.mjs` |
| D-LVL-03 | Звёзды считает сервер (bounds/1): `levelEnd.moves` = потерянные жизни; ★ ≤ 9, ★★ ≤ 1, ★★★ = 0 | Правило звёзд 00_MASTER выражено порогами bounds/1; клиент звёзды не считает; continue автоматически даёт ★ (D-10-07) |
| D-LVL-04 | `seed: perAttempt`, `score.max` по ГДД 11 D-11-04, `durationMs.min` = 1 + 19·spawnInterval + 1 − 1 s (58.0/48.5/39.0 s) | Случайность ИИ/дропа — PRNG попытки; границы — из правил ГДД, не «из головы» |
| D-LVL-05 | Жанр недетерминирован → `docs/levels/VALIDATION.json` вместо SOLVER.json; полосы сложности по TI заданы брифом (`docs/levels/CURVE.json`), rest — стадии 11 и 21 | В QUALITY_TARGETS полос нет; TI фиксирован формулой состава ГДД, темп регулирует открытость карты |

## Сервисы платформы (шаг «Сервисы платформы», 19.11.2026)

| ID | решение | обоснование |
|---|---|---|
| D-SVC-01 | `realtime` — **MVP** (отменяет «не используется» в 31 `plat.services` и BUILD_BRIEF) | Механика может его использовать: бустеры выдаёт сервер (покупка, daily, награды уровней) — счётчики обновляются по `realtime:inventory.balance.changed`, покупка подтверждается по `iap.order.granted`, `configs.reload` применяет тюнинги без перезапуска. «Нет мультиплеера» — не причина исключения |
| D-SVC-02 | `scheduling` — **Product** (не «не нужен») | Подходит механике (ивенты Siege Weekend, периоды досок, инбокс), но по MCP модуль beta и требует активации владельцем API; live-ops в MVP выключен |
| D-SVC-03 | `ads` — не нужен | Запрещено рамками потока (рекламы нет совсем) |
| D-SVC-04 | Лидерборды подключаются `leaderboardsModule()` без `{boards}`; клиент не вызывает `submit`, пока `canSubmit === false` | По MCP docs (миграция rc.21→rc.25) опции `boards` нет; у игры `clientAuthoritative: false` → очки пишет сервер из источника progress (закрывает D-31-06) |
| D-SVC-05 | Сид стадии — из `progress.beginAttempt` (seed передаётся в `levelEnd`), mulberry32 игры инициализируется им | Без серверного seed `levelEnd` вернёт `verified: false`; сервер проверяет результат |
| D-SVC-06 | Валюты в MVP нет (подтверждение D-00-06); инвентарь, daily и магазин — включены | Правило экономики: есть расходуемые бустеры — их выдают награды и продаёт магазин; Scrap — следующий этап (15 `meta.next`) |
