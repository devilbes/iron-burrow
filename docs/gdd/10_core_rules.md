# 10 — Core rules (`core.`)

Источник чисел — `00_MASTER.md` §5–6, §9. Новые числа помечены *new* и живут в remote config `game.balance` (ключи `core.*`); бустеры — `game.boosters`, power-up — `game.powerups`.

## 1. Состояние стадии

`intro → playing ⇄ paused → cleared | defeated → continue → playing` (из `defeated` также выход в S08 без continue).

| state | вход | что идёт | выход |
|---|---|---|---|
| `intro` | старт стадии | баннер `STAGE N` (Siege: `WAVE 1`), симуляция стоит | через `core.intro_s` → `playing` |
| `playing` | — | тики симуляции | Esc/кнопка Pause/скрытие вкладки → `paused`; исход тика → `cleared`/`defeated` |
| `paused` | — | всё заморожено (таймеры тоже) | Resume → `playing` |
| `cleared` | убит 20-й враг | вражеские пули удаляются, игрок может ездить, исход больше не меняется | через `core.clear_delay_s` → S07 |
| `defeated` | Core разрушено или lives = 0 | симуляция стоит, только анимация взрыва | через `core.defeat_delay_s` → S08 |
| `continue` | S08 → Spare Hull (≤1 на стадию / run) | см. D-10-07 | баннер `READY` `core.continue_ready_s` → `playing` |

D-10-01: потеря фокуса/`visibilitychange=hidden` всегда ставит `paused`; авто-resume нет.

## 2. Шаг симуляции и детерминизм

- Фиксированный `dt = 1/60` s; аккумулятор кадра, не более `core.max_ticks_per_frame` тиков за кадр (лишнее время отбрасывается).
- D-10-02: координаты — целые единицы, **1 cell = 600 u** (half = 300 u, quarter = 300 u). Скорость за тик: player 30 u, scout 36, grunt 18, gunner 24, brute 18, bullet 90, fast bullet 135. Никаких float в позиции.
- PRNG — **mulberry32**, отдельные потоки от `runSeed` (uint32): `rngAI = mulberry32(runSeed ^ 0xA1A1)`, `rngDrop = mulberry32(runSeed ^ 0xD20D)`, `rngGen = mulberry32(runSeed ^ 0x6E6E)`. `Math.random`, `Date.now` в симуляции запрещены.
- `runSeed` выбирает клиент на старте стадии (crypto uint32); симуляция = f(seed, карта, лог команд по тикам). Тесты и `sim:*` передают seed явно.

## 3. Движение танка

- Танк — AABB `core.tank_size` = 1.0 cell (600 u), позиция = левый верхний угол. 4 направления.
- D-10-03: при повороте на 90° перпендикулярная координата выравнивается к ближайшему кратному 300 u (ровно посередине — к большему). Если выровненный AABB пересекает твёрдое, выравнивание не делается, поворот всё равно применяется. Разворот на 180° — без выравнивания.
- Твёрдое для танка: quarter с `brick`/`steel`, клетка `lava`, клетка Core, край поля. `roots`, `oil`, `empty` — проходимы.
- Движение за тик: сдвиг на speed·dt; при пересечении твёрдого позиция зажимается до касания.
- `oil`: если центр танка на `oil` и танк перестал ехать по своей воле (игрок отпустил ввод), он скользит ещё `core.oil_slide` = 0.5 cell в направлении взгляда со своей скоростью (или до упора).
- Танк-танк: ход отменяется, если площадь пересечения с любым другим танком увеличилась бы. Уже перекрытые танки могут разъезжаться. Контакт не наносит урона.

## 4. Пули

- Box 0.25×0.25 cell (150 u), центр на оси танка, стартует у переднего края. Игрок: L0 — 1 пуля на поле, 9 c/s; L1 — 1, 13.5 c/s; L2 — 2, 13.5; L3 — 2, 13.5, ломает steel. Плюс `core.player_fire_cooldown_s`. Враг: 1 пуля, 9 c/s (gunner 13.5).
- Инвариант: шаг пули за тик < 150 u (скорость ≤ 15 c/s), поэтому подшагов нет — дискретная проверка не пропускает quarter и встречную пулю.
- **Пуля-тайл (по четвертям)**: попадание = box пули пересёк сплошной quarter (`brick`, `steel`). Урон — полоса шириной 1 cell поперёк полёта, центр на оси пули, глубиной в один ряд четвертей (тот, где попадание); рушатся quarters, перекрытые полосой ≥ половины. `brick` — любой пулей; `steel` — только L3; иначе пуля гасится без урона steel. `lava/roots/oil/empty` пули пролетают. Край поля — пуля исчезает.
- **Пуля-пуля**: пули игрока и врага при пересечении box взаимно уничтожаются. Вражеские пули друг с другом не сталкиваются (D-10-04).
- **Пуля-танк**: враг от пули игрока теряет 1 HP (carrier при первом попадании роняет power-up); пуля врага по врагу — гаснет, урона нет; по игроку — смерть, если нет щита (spawn shield / bubble), иначе гаснет.
- **Пуля-ядро**: любая пуля (и игрока) в клетке Core → Core разрушено → поражение.

## 5. Порядок разрешения за тик

1. Команды ввода тика (движение, огонь, бустеры).
2. Таймеры: эффекты, power-up TTL, спавн, щиты, кулдауны.
3. Бустеры (§7), затем спавн врагов и respawn игрока.
4. Решения ИИ (`12_content_generation.md`).
5. Движение танков: игрок, затем враги по id ↑.
6. Выстрелы (новые пули).
7. Пули по id ↑: перемещение всех → пары пуля-пуля → для каждой: танк (ближайший по ходу) → Core → тайл → край. Одна пуля = одно событие.
8. Подбор power-up (AABB игрока пересёк клетку power-up).
9. Исход: **defeat (Core или lives = 0) приоритетнее clear**.

## 6. Краевые случаи

- E1. В одном тике пуля врага попала в Core, а пуля игрока убила 20-го врага → `defeated`.
- E2. Игрок с последней жизнью убит в том же тике, когда умер 20-й враг → `defeated`.
- E3. Пуля grunt попала в brute → пуля исчезла, brute цел (дружеского огня у врагов нет).
- E4. Игрок выстрелил вниз по своему ядру сквозь пробитую стену → Core разрушено → `defeated`, причина `core`.
- E5. Встречные пули игрока и врага пересеклись в клетке над Core → обе исчезли, Core цел.
- E6. Две пули в одном тике бьют один quarter → первая (меньший id) рушит, вторая летит дальше, если впереди пусто.
- E7. Танк упёрт в brick и стреляет → пуля стартует внутри quarter и рушит его в этом же тике.
- E8. Игрок погиб, его пули ещё летят → продолжают действовать (убивают, начисляют очки).
- E9. Пауза во время spawn shield → таймер щита стоит.
- E10. `quake` убил последних врагов → `cleared`, очков за них нет.

## 7. Жизни, спавн, бустеры

- Lives = 3 (+1 за Spare Hull pre-stage); lives — запас танков с текущим. Смерть: lives −1, gun → L0; если lives = 0 → `defeated`, иначе respawn через `core.player_respawn_delay_s` в (4,12) со щитом 3 s. D-10-05: точка игрока никогда не блокируется (перекрытие разрешается §3).
- Враги: первый спавн через `core.first_spawn_delay_s`, далее таймер `spawnInterval`. Если alive (включая появляющихся) = maxAlive — спавн ждёт и происходит в первый тик, когда место освободилось. Точки по ротации (0,0)→(6,0)→(12,0) (индекс растёт на каждый спавн). **Блокировка**: если клетку точки перекрывает танк — берётся следующая точка ротации; заняты все три — повтор в следующем тике. Анимация `core.enemy_spawn_anim_s`: враг не твёрд и неуязвим, после — активен.
- Gun level переносится только при переходе кнопкой `Next` из S07 (D-10-06); иначе старт с L0.
- D-10-07 continue: lives = 2, Core восстановлено (стена — нет), все пули удалены, враги на поле возвращаются в начало очереди (не засчитаны), игрок со щитом 3 s. Стадия с continue даёт не больше ★.

| booster | хоткей | лимит (stage / Siege run) | условие кнопки |
|---|---|---|---|
| `bst_bubble` | 1 | 2 / 4 | игрок на поле, щита нет |
| `bst_shockwave` | 2 | 1 / 2 | есть активный враг (не в анимации спавна) |
| `bst_fortify` | 3 | 1 / 2 | эффект fortify/rebar не активен |
| `bst_hull` | — | pre-stage 1 / 2; continue 1 / 1 | S04 / S08 |

Общие правила: только в `playing`, inventory > 0, кулдаун `core.booster_cooldown_s`. Эффект применяется в тике команды; списание через `inventory.consume` (D-10-08: оптимистично для бустеров в бою, до 3 повторов, затем кнопка неактивна до конца стадии; `bst_hull` — только после подтверждения; см. 15 D-15-02; команда пишется в лог для детерминизма). `shockwave`: активные враги убиты, засчитаны с очками, carrier роняет power-up. `fortify`/`rebar`: 8 клеток Core wall → steel целиком; quarters под танком дозаполняются, когда танк уйдёт; по окончании стена становится целым brick. Таймеры эффектов не суммируются: `max(остаток, новый)`.

Power-up (подбирает только игрок): `star` на L3 — только очки; `freeze` — враги (и новые после спавна) не двигаются, не решают и не стреляют, их пули летят; `quake` — активные враги убиты без очков и без дропа; `hull` в Siege тоже +1 life. D-10-10.

D-10-09 Core wall: блок 3×3 cols 5–7, rows 10–12 без Core = ровно 8 клеток.

`core.threat` (событие для туториала и метрик): вражеская пуля разрушила quarter Core wall **или** центр врага ближе `core.threat_radius` к центру Core.
