# tests

Тесты без сети и без установки SDK. Все — `npm run test:unit`: `tests/*.test.mjs` и
`tests/build/*.test.mjs`; один файл — `node --test tests/strings.test.mjs`. Вместе со сборкой,
записями и галереей — `npm run check` (`scripts/check.mjs`): одна сборка, все провалы в конце разом.

- `tests/*.test.mjs` — быстрые (весь набор — около секунды): без сборки проекта и без браузера. Их
  запускает и `npm run check:fast` — после проверки типов и бандла; `npm run check:fast -- --only
  "<часть имени теста>"` — только подходящие по имени (ни одного — провал, а не «прошло»).
- `tests/build/*.test.mjs` — каждый тест собирает свою копию проекта (`helpers/build-fixture.mjs`);
  файлы идут параллельно. Это секунды–минуты: только в полном наборе (`npm run check`,
  `npm run test:unit`), когда правки закончены.

Тест, который собирает проект или открывает браузер, в `tests/*.test.mjs` не кладут
(`test-set.test.mjs`).

| Файл | Что проверяет |
|---|---|
| `build/files.test.mjs` | что сборка кладёт в `dist/`: `vendor/` и `assets/` целиком, без исходников арта; `assetUrl` |
| `build/bundle.test.mjs` | бандл esbuild (вход, куски, карты, минификация JS/CSS/HTML), import map, заголовок и язык страницы |
| `build/debug.test.mjs` | debug-код: есть в локальных сборках, нет в prod |
| `build/types.test.mjs` | проверку типов сборки и `scripts/typecheck.mjs` с SDK и без: без тихого отката; `--no-typecheck` — только бандл, в prod не действует; инкрементальная проверка повторяет ту же ошибку |
| `build/startup.test.mjs` | видимые состояния запуска собранного входа (`helpers/startup.mjs`) |
| `test-set.test.mjs` | `npm run test:unit` запускает каждый файл `*.test.mjs` из `tests/`; в быстром наборе `tests/*.test.mjs` нет сборок и браузера |
| `grants.test.mjs` | вход дня (`src/boot/grants.ts`): одно чтение прогресса, один `login`, без ожидания выдачи и без повторного чтения |
| `game-ports.test.mjs` | `GamePorts` на поддельном SDK с журналом запросов: один `progress.init` за сессию, записи уровней один раз, конец уровня без ожидания награды, `currentLevel()` после победы без чтения, сохранение только по вызову игры |
| `assets.test.mjs` | `scripts/assets.mjs` (`npm run assets`) на картинках, которые делает сам тест: 1x — ровно половина 2x, пиксель — среднее 2×2 с весом по прозрачности; цвет под прозрачностью не попадает на края; нечётная сторона 2x — проблема с именем файла и ближайшим чётным размером; повторный запуск ничего не переписывает; `--check` называет все проблемы разом (нет 1x, не половина, отличается, без пары 2x) и ничего не меняет; без пары 2x — проблема только в `assets/game/`, `assets/ui/`, `assets/images/`, в `assets/skin/` и других папках один файл допустим, а пара с `-2x` проверяется так же; WebP рядом с PNG; `--defringe` — кольцо цвета-ключа уходит, картинка остаётся; картинки самого проекта — верные пары |
| `levels-hash.test.mjs` | `scripts/levels-hash.mjs`: хеш первого диапазона из `levels.main/set.json` равен записанному |
| `strings.test.mjs` | запись `localization/strings` (`configs/remote/localization/strings.json`) склеена из частей `strings/*.json` (`npm run strings`); ключи `shell.*`/`screen.*` из кода есть в ней для базового языка, лишних нет; есть `shell.title`; `LOCALES` (`src/screens/index.ts`) = опубликованные языки `localization/locales`, у каждого все ключи |
| `records.test.mjs` | `scripts/validate-records.mjs` (`npm run records`): образцы `configs/remote/` проходят; схема сервера `schemas/<scope>.json` (или по шаблону `levels.*.json`) берётся раньше SDK; разделы без схемы перечислены, а не пройдены; правило `profileProjection` и связи между записями; id из `src/boot/ids.ts` и предметы `TOP_BAR` есть среди записей (часть с SDK без `vendor/` пропускается) |
| `skin-readiness.test.mjs` | скин игры (`src/skin/`): `theme.css` задаёт все цветовые входы стока и не задаёт на `:host` производные; файлы картинок и шрифтов есть и подключены; имена шрифтов совпадают; в листах нет литеральных цветов, `!important`, `data-testid`, `nth-child`, условий по пикселям; вес ≤ `SKIN_WEIGHT_LIMIT`; предметы каталога (`configs/remote/inventory.catalog/`) без картинки в `ITEMS`, со стоковым значком или без названия — в отчёте. `SKIN_STRICT=1` — ещё и ни одного цвета со стоковым значением и ни одного такого предмета |
| `hud.test.mjs` | плитки HUD и счётчики топбара (`HUD`, `TOP_BAR` в `src/screens/index.ts`, правила — `src/shell/hud-plan.ts`): сторона по смыслу, порядок, что может и чего не может запись `ui.hud/layout`, плейсменты и отсчёт плитки оффера, капсулы модулей, что открывает счётчик топбара и его «+» (по умолчанию магазин, без него — нет «+»); готовность — список плиток и счётчиков без иконки скина или без строки |

| `skin-gallery.mjs` | галерея окон кита с тестовыми данными, без сети: 20 видов (с `login` — окно ManyPlay ID) в 390×844, 844×390, 1280×720, `home` — как поставляется шаблон, без нижнего меню, `home-menu` — с нижним меню из трёх тестовых пунктов, `home-hud` — HUD и топбар игры с событием, оффером с отсчётом и вторым ресурсом, `home-hud-full` — больше плиток, чем вмещает колонка, `game-window` — окно игры через `ctx.window.open` (звёзды, строки счёта, две кнопки), `game-overlay` — слой `ctx.overlay`, `buttons` — все виды кнопок в двух ширинах; снимки и отчёт «сток ещё виден» (элементы со стоковым цветом, стоковые картинки, виды без отличий); `SKIN_STRICT=1` — провал при любом остатке стока. | `browser-startup.mjs` | в браузере с настоящим SDK и API стенда: запуск, бюджет запросов за запуск и 10 с простоя (`BUDGET`), главный экран без нижней панели (её строка — 0 px), Play главного экрана → заглушка → Close спрашивает окном игры (диалог кита, содержимое игры в нём) → «Stay» оставляет уровень, «Leave» — главный экран; все окна сервисов открываются и закрываются, у каждого окна затемнение — окно браузера от края до края, топбар под ним (1280×720, 844×390, 390×844); «+» монет открывает магазин; профиль — строки игры в двух колонках без id и прочерков, настройки → «Войти» → окно входа ManyPlay ID и запрос провайдеров (почта не вводится), браузер с русским — игра и окна кита на английском (опубликован только `en`), за прогон один `progress/me/init` и ни одного `game-states`, нет ошибок в консоли |

Браузерная проверка (после `npm run build`, Playwright с Chromium вне проекта, на стенде
создаётся новый гость): `PLAYWRIGHT=/path/to/node_modules/playwright node tests/browser-startup.mjs`.
Скриншоты — в каталог из `SHOTS`, по умолчанию `tmp/shots`.
Проверка полного артефакта в `build/bundle.test.mjs` требует пакетов SDK и без них пропускается.

Снимок одного экрана игры (Playwright вне проекта, без сети; `dist/` старше исходников пересобирается
сам, без проверки типов):
`PLAYWRIGHT=/path/to/node_modules/playwright [SHOTS=tmp/shots] npm run shot -- --route game --size 844x390`
→ `<SHOTS>/screens/game-844x390.png`. Экран рисуется на странице галереи: оболочка в скине игры,
топбар, тестовые данные; `ctx.game` отвечает из `configs/remote/levels.<набор>/`
(`tests/skin-gallery/test-ports.js`: уровень — `--level <n>`, конец уровня с победой — три звезды,
сохранения нет). `--watch` держит браузер и после каждой правки `src/`, `assets/`, `index.html`
пишет тот же файл заново (доли секунды на снимок); остановка — Ctrl+C. По умолчанию — `home`,
`390x844`, уровень 1. Это взгляд на экран, а не проверка: ошибки страницы — код 1, остальное
проверяют галерея и `browser-startup.mjs`.

Галерея скина (после `npm run build`, Playwright вне проекта, без сети):
`PLAYWRIGHT=/path/to/node_modules/playwright [SHOTS=tmp/shots] [SKIN_STRICT=1] node tests/skin-gallery.mjs`.
Частичный прогон для правок — `… node tests/skin-gallery.mjs --only home,shop --size 844x390`
(или `VIEWS=home,shop SIZES=844x390`): пишет `PARTIAL RUN`, никогда `PASS`, с `SKIN_STRICT=1` код
выхода не 0; приёмка — полный прогон без этих опций. `--jobs <n>` (`JOBS`) — сколько страниц
рисуют одновременно (по умолчанию до 4). Порядок работы —
[custom-window-skin.md](../docs/platform/recipes/custom-window-skin.md#проверка).
Снимки и `report.json` — в `<SHOTS>/gallery/`.
