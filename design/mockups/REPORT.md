# Iron Burrow — макеты собственных экранов

Готовы 5 адаптивных HTML-макетов × 3 размера = 15 видов: Lobby, Stage Map, Game, Stage Clear, Defeat. Навигация — GALLERY.html. Растр — assets/ui/screens/, перечень — SCREENS.json, проверенный список непустых файлов — FILES.txt. Сервисные окна, загрузка, ошибки и длинные строки не создавались.

Пять иллюстраций созданы встроенным Codex image_gen параллельно отдельными сабагентами, по одному вызову и сохранению на экран. Точные запросы и исходные пути инструмента — ASSETS.md каждого экрана. Каждый запрос использовал STYLE_REF.png и художественные разделы UI_ART_BIBLE дословно; отдельного готового шаблона в библии нет. Исходники только -2x.png, чётные стороны. Уменьшение и WebP сделаны одним общим `npm run assets -- --webp=85 assets/ui/screens`. Пять файлов 2x + пятнадцать производных; problems = 0. Полный вывод — ASSETS_PROCESS.txt / ASSETS_CHECK.txt. Скрипт шаблона печатает таблицу даже при успехе: «без единой строки» для этой версии невозможно, exit = 0 и problems = 0.

Кнопки построены настоящим createViewComponent + button UI Kit. Нейтральный слой расширен общим preview-адаптером по уже описанному id-button-face из docs/skin/map.json. Готового подключаемого скина и обещанного контракта имён кнопок в design/system/SYSTEM.md нет. Новые варианты рамок/кнопок не генерировались; SDK, UI Kit, базовая тема и design/system не менялись. На интеграции общий preview-адаптер должен уступить готовому скину. Макеты используют статические демонстрационные данные, не заменяют сервисы SDK.

92 игровых ассета и 24 детали скина из ГДД принадлежат соседним шагам. Их не создавали и не подменяли этими пятью композиционными иллюстрациями. Поле S05 — визуальный эталон состояния уровня; реализация механики будет использовать отдельные тайлы/спрайты. Файлы чужих бинарных иконок, намеренно отсутствующие в worktree, проверочный сервер читает из основного checkout только для чтения. Никакого восстановления этих файлов в чужие каталоги нет.

## Проверки и пределы результата

- Браузер: 15/15 видов, без переполнений, битых изображений, неразрешённых ключей и ошибок JS; видимые кнопки ≥48 px. VERIFY.json содержит размеры и DOM-факты. HTML получает data-ready после шрифтов/изображений; data-window соответствует ГДД.
- Общий browser-прогон после сведения; повторялся только для найденных ошибок подключения CSS и затем группы замечаний судей. Картинки не перегенерировались, обработка не повторялась. CONTACT_SHEET.png и GRAYSCALE.png — самопроверка, не замена HTML-макетов.
- Два независимых судьи: JUDGE_ART.md и JUDGE_LAYOUT.md. Исправлены мешающий подписям маршрут карты, высоты вкладок/бустеров, группировка controls и высоты ряда результата. Исходные баллы сохранены, независимого повторного утверждения нет. Material gap между иллюстрациями и preview-кнопками остаётся долгом подключения скина. Consistency по утверждённому экранному эталону не подтверждена: foundation содержит только материальный якорь.
- Самопроверка по художественной библии: горячий акцент выделяет primary/Core, иерархия сохраняется в grayscale. Из результатов исключена отдельная карточка оффера, из экранов — лишние сервисные состояния. Замечания о горячих стенах поля и стилистической интеграции награды сохранены в ревью; визуальный PASS не заявлен.
- `npm run check` с Playwright запущен один раз. Сборка и пары растров прошли; общий результат не зелёный из-за записей/шаблона вне writeSet. Полный вывод — PROJECT_CHECK.txt.
- Официальный palette: FAIL конфигурации — нет gates.art.budgetOfRoot, art.paletteDeltaEMax/Percentile не измерены. Порогов самостоятельно не выдумывали. PALETTE_GATE.txt.
- `studio-gates visual` сравнивает внедрённую игру с макетами, а внедрение здесь не выполнялось. Попытка этого сравнения остановлена; официальный df-visual PASS не заявлен. VISUAL_GATE.txt.
- Отдельный запуск стенда — STARTUP_CHECK.txt; это проверка существующего приложения, не макетов.

## Чего не хватает у платформы / для сведения

1. Передать gates.art.budgetOfRoot через gate-facts и пороги palette из источника качества — тот же незакрытый пункт verify-design-foundation.
2. Готовый подключаемый скин и контракт имён его контролов: SYSTEM.md содержит правила стиля, но не экспортируемые компоненты/имена. Использован описанный в docs/skin/map.json общий preview-адаптер; финальная визуальная приёмка — после подключения скина.
3. Общие записи и шаблон расходятся: localization/strings без defaultLocale/locales, в коде остались отсутствующие item_coins / placement_shop / reward_daily; пять unit-провалов относятся к этому расхождению. Править configs, src/boot и src/skin в этом шаге нельзя.
4. package-lock.json не добавлялся: package.json и файлы установки защищены инструкциями; scripts/assets.mjs и команда assets уже есть, прежнее замечание об их отсутствии устарело.

Решения с обоснованиями внесены в docs/gdd/DECISIONS.md (D-MOCK-01…05). Итог: артефакты экранов созданы и механически проверены; общая/визуальная приёмка остаётся с явно указанными долгами.

Уточнение общего прогона: после сборки и unit-части команда завершилась сигналом SIGTERM (143); полного отчёта галереи скина нет. Это **неполный FAIL**, не зелёная сдача. Unit-часть: 130 тестов, 122 PASS, 5 FAIL, 3 SKIP. Повтор общего прогона не выполнялся: перечисленные ошибки вне writeSet, а владелец запросил один общий прогон.

Отдельный запуск на стенде завершён: STARTUP_CHECK.txt — **PASS** (три размера, окна существующего шаблона, вход, сетевой бюджет, отсутствие ошибок консоли). Это не приёмка реализации Iron Burrow: приложение по-прежнему содержит штатную игровую заглушку, которую данный шаг не меняет.
